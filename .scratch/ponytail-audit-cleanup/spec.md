# Ponytail：清理 v13 死代码与无效绑定

Status: ready-for-agent

## 问题陈述

Gamebox 作为浏览器小游戏合集已经可以正常运行，但 v13 迁移完成后仍遗留了可避免的维护负担。代码库中仍有孤立的暂存槽 API、被忽略的 adapter 参数、只用于校验的配置字段、未使用的运行时元数据、无消费者的计时状态、过时的公共导出，以及源码和测试中的大量无效 import。当前 no-unused 诊断报告 32 个源码诊断和 290 个测试诊断。

这些遗留内容让代码库更难导航，也让真正生效的契约不够明显。多个名称仍暗示已经不存在的行为，增加了后续维护重新启用废弃路径或引入第二个行为来源的风险。

## 解决方案

对审计出的范围执行一次不改变行为的清理。删除已确认的死代码，合并只做转发或忽略参数的 adapter，移除不会影响运行时行为的配置字段，并将快照收敛到当前 UI 和游戏 seam 实际消费的数据。

保留有意设计的 v13 架构：`GameSession` 与 `DogItemRuntime` seam、`LevelGenerator` 与可解性 seam、Worker 准备与同步 fallback、集中且经过校验的配置、通用游戏目录契约、动画协调以及现有测试 profile。最终代码应减少名称和路径，同时保留所有用户可见规则，以及仍有仓内消费者的公共 seam。

## 实现决策

- 本次只做删除和定向收缩。不新增替代框架、兼容层、依赖或推测性抽象。
- 保留现有最高 seam：`GameSession`、`DogItemRuntime`、`LevelGenerator`、`GameDefinition`、`GameboxApp`、Worker 准备契约和 v13 测试 profile runner。不新增生产 seam。
- 删除废弃的仅图案暂存槽模型及其无用 wrapper。保留当前方块入槽、特殊机制准备、三消结算和成功三消效果流程。
- 只有在确认没有仓内消费者时，才删除死 helper 导出和迁移遗留。范围包括无用的随机/进度/可解性/配置 helper、废弃容量常量、未使用的默认运行时定义、未使用视觉常量、冗余类型别名、只有一个 `destroy` 方法的控制器类型声明和 no-op 引用。
- 保留狗游戏入口模块作为有意的公共入口，但删除已确认无用的 re-export，不删除入口本身。
- 内置道具次数直接读取经过校验的 v13 道具次数规则。在注入自定义运行时定义的边界保留数值归一化，以便 focused 测试继续提供自定义定义。
- 将 `DogItemState` 收敛到当前道具组渲染器和运行时控制器实际消费的数据：身份、显示名称、剩余次数和可用状态。活动目标类型与活动视觉反馈保留在运行时快照/动作层，因为当前流程在那里消费它们。
- 删除未使用的三消目标图案投影及其 session 方法。当前目标 UI 和控制器继续以方块 ID 目标列表为来源。
- 删除耗时 debug 状态及其运行时记录，因为当前渲染器、app 契约和测试都不消费它。
- 删除只用于校验或固定不产生运行时变化的配置字段，包括重复的关卡边界、未使用的棋盘和锁槽位置设置、未使用的默认/上限标志、未使用的余数策略和不可到达的非 floor 预算分支。继续校验并使用剩余的行为配置。
- 删除未使用的道具文案图标数据和未使用的逐道具运行时元数据。道具视觉继续来自现有配置的道具资源；道具描述继续服务于实际渲染的道具组编辑器。
- 当底层经过校验的配置 helper 已提供保证时，删除进度委托中的重复校验和防御性复制。
- 从测试 profile schema 和 runner 校验中删除无效的 `runUI` 字段。保留现有 core/UI 命令行为和 profile 选择规则。
- 清理源码和测试中的无用 import 与参数。不为了满足行数而改变测试意图；将测试更新为直接消费当前契约。
- 保持所有现有特殊机制 handler、逻辑方块单位计算、层叠关系图缓存、可解性搜索、难度筛选、回放校验、Worker fallback、动画生命周期、音效、游戏进度、导航和响应式样式的行为不变。
- 不修改依赖清单。当前依赖仍分别由 Vite、TypeScript、Vitest/jsdom 和 Playwright 使用。

## 测试决策

- 使用现有 full QA profile 作为验收 seam，因为本次清理跨越生成器、可解性、运行时、公共契约、游戏启动、Worker、UI 和测试基础设施。运行 `pnpm test:qa`，不要与 `pnpm test:affected` 叠加。
- 清理后运行 `pnpm exec tsc --noEmit --noUnusedLocals --noUnusedParameters`，确认审计出的无效绑定已经消失。这是验证命令，不是新的生产抽象或测试 profile。
- 现有 `LevelGenerator` 测试继续作为关卡边界、形状、机制、可解性、难度、回放、fallback 和 `runSeed` 确定性的主要行为 seam。
- 现有 `GameSession` 和道具运行时测试继续作为方块入槽、相邻三消、逻辑方块单位、锁槽、道具计划、道具次数、原子提交和终局状态的主要行为 seam。
- 现有 `GameboxApp`、`GameDefinition` 和结果页测试继续作为注册、游戏目录导航、游戏进度、道具组持久化、结果操作和生成失败的主要行为 seam。
- 现有动画、渲染器、特殊机制 UI、音效、Worker fallback 和跨浏览器测试继续作为 DOM、时序、输入锁、反馈和浏览器行为的主要行为 seam。
- 更新提及已删除元数据或导出的断言，让它们验证当前外部行为。不用新的私有状态断言替代已删除的实现细节断言。
- 保留当前用于独立校验生成器的几何测试 oracle，不直接调用被测实现来替代它们。
- 成功验证必须包含 full profile 的核心测试、Worker fallback、随机回归、Chromium 流程、跨浏览器流程、页面构建、diff 检查和改动文件行数检查。
- 这是代码和测试清理而非新用户功能，因此不新增 E2E 场景；只有在删除 API 暴露出现有行为缺口时才补充场景。

## 范围之外

- 不改变任何用户可见游戏规则、特殊机制、道具效果、暂存槽规则、关卡生成算法、难度目标、奖励公式、回放格式或 `runSeed` 语义。
- 不因为文件被拆分就替换有意保留的 v13 模块边界、Worker seam、层叠关系图缓存、通用游戏目录契约、集中配置契约、动画 seam 或 CSS 片段。
- 不新增游戏、道具、特殊机制、profile、依赖、构建工具、linter 或运行时抽象。
- 不重新设计公共游戏目录或结果 API；只删除已确认没有仓内消费者的导出。
- 不改变游戏进度持久化、匿名用户身份、导航历史、离开保护、音效策略、响应式布局或资源托管。
- 不处理清理过程中顺带发现的正确性、安全性或性能问题；另行记录并进行普通 review。
- 不为了与生产求解器共享实现而重写独立的 E2E 可解性 helper。
- 如果发现未知的外部消费者，不在未解决其归属和兼容要求前删除相关符号。

## 进一步说明

- 仓库是私有应用，因此本 spec 假定仓内消费者定义受支持 API。如果之后发现外部消费者，应先保留或显式迁移对应符号。
- 清理后除预期的 spec 和实现改动外，不应留下生成产物或依赖变化。
- 审计估计约可删除 300 行代码，且没有可删除的依赖；实现时应核对实际减少量，不为达到估计值而填充 diff。
- 在实现 ticket 的评论中记录实际聚焦检查、no-unused 诊断结果和单次批量 `pnpm test:qa` 结果。
