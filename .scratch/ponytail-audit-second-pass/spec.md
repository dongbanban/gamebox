# Ponytail：第二轮仓库精简

Status: ready-for-agent

## 问题陈述

Gamebox 已完成一轮 v13 清理并保持完整游戏闭环，但仓库仍维护若干不会增加用户价值的第二实现和基础设施层。最明显的是：浏览器流程拥有一套约 400 行、复制生产规则的独立关卡求解器；一次性狗图导出程序在缺少源图和受管依赖的情况下长期留存；测试 profile、seed 和 QA 执行开关进入生产配置并同时被主页面与 Worker 打包；测试文件发现、case 到入口映射和文件行数检查重复实现了测试框架或系统工具已有的能力。

固定的五种特殊机制还通过可注入 handler registry 传遍局内状态、可解性和乱序流程，尽管仓内没有自定义 handler 消费者。进度、暂存槽和三消代码中也残留手写 UUID fallback、不可达 legacy 上限、零消费者类型/helper、重复转换与复制，以及可由数组标准方法表达的删除循环。

这些内容增加了修改面、公共名称、浏览器产物、测试维护成本和规则漂移风险。第二轮审计估计可净删约 900 行，不删除依赖。目标不是重新设计游戏，而是在保持当前用户行为、领域规则和验证强度的前提下，让每条规则与工具行为只保留一份实现。

## 解决方案

执行一次以删除和复用为主的第二轮精简：浏览器通关流程使用已验证关卡携带的 `solutionPath`，不再复制生产求解规则；测试 profile 与 QA 编排退出生产配置，保留为测试基础设施自己的单一配置；测试 case 改用 Vitest 与 Playwright 的原生发现规则；文件长度检查改用现成系统命令；固定特殊机制改为共享的直接分派函数，不再暴露未使用的可插拔 registry。

删除不可复现的一次性资源生成程序、无消费者声明和不可达分支。统一暂存槽方块转换与复制，使用浏览器及 JavaScript 原生能力替代 UUID、History URL 和数组删除样板。所有变更保持「狗了个狗」关卡尝试、特殊机制、道具、游戏进度、回放、Worker fallback、动画、音效、可访问性与视觉行为不变。

本轮明确重开两项旧决定：ADR-0007 中“测试 profile 属于生产 v13 配置”的部分，以及上一轮 Ponytail 清理中保留独立 E2E 求解器和特殊机制 handler registry 的决定。实现时同步更新相关 ADR、领域文档、agent 验收说明和测试说明，使文档只描述最终结构。

## 实现决策

- 本次只做删除与合并。不新增依赖、不引入替代框架，也不为未来可能出现的消费者建立抽象。
- 保持现有用户可见行为和领域规则不变。实现过程中发现的正确性、安全性、性能或视觉问题，除非维持当前行为所必需，否则另行处理。
- 使用现有完整 QA 命令作为唯一顶层验收 seam，因为改动横跨生产契约、游戏进度、关卡生成、浏览器流程和测试基础设施。
- 使用已验证关卡的现有 `solutionPath` 替换浏览器专用独立求解器。通过当前可观察游戏状态取得关卡号和 `runSeed`，使用现有关卡生成 seam 复现同一关卡并点击所得路径；不新增生产调试接口，也不暴露新的 DOM 解法属性。
- 保留生成器、可解性、回放、`GameSession` 与随机回归测试作为 `solutionPath` 有效性的证明；E2E 只证明真实浏览器能够执行该路径并到达预期结果页。
- 从 `DogV13Config`、运行时配置源、运行时校验、狗游戏公共导出和 Worker 载荷中删除测试 profile；测试专用 profile 数据只归 Node 测试基础设施所有。
- 保留 `focused`、`smoke` 和 `full` 三个 profile 名称。关卡检查点、固定 seed、压力范围与命令意图只保留在一份测试专用来源中，不再同时映射到浏览器 TypeScript 与 Node JavaScript。
- 删除只被测试或 QA 脚本消费的生产 helper。仍有价值的测试报告 helper 可以放在随机回归测试附近。
- 更新 ADR-0007：集中 v13 配置继续覆盖用户可见游戏行为、生成、难度、资源、音频、动画与 UI；QA profile 明确归属于测试基础设施配置。
- 将嵌套 Vitest case 与 Playwright case 改为框架原生发现命名。通过测试级标注或现有 runner 配置设置 jsdom；确认全部既有测试均被收集后删除代理入口。
- 精简受影响测试路由：TypeScript 测试使用 Vitest 的 related/import graph；E2E helper 或共享浏览器行为变化时直接运行小规模浏览器套件，不再维护 case 到入口的映射。
- 路由调整后保留现有验证词汇和 ticket 策略；同步更新 agent 指令与 README，使其描述直接测试发现，而不是嵌套 case 映射。
- 使用 Git 与标准 shell 行数工具替代自定义改动文件行数解析器，并保留当前阈值语义。若未来取消阈值，直接删除检查，不再建立新的策略引擎。
- 将 v13 特殊机制集合视为封闭集合。用共享直接函数处理可匹配性、入槽和成功三消效果，删除 handler 对象、handler Map、重复/缺失校验、可注入 handler 选项及反复透传的 handler 参数。
- 对确实可变的机制行为继续传入已验证配置，尤其是冻结融化进度；不得用新字面量替代集中配置值。
- 运行时与求解器的机制状态变化继续共享一份实现；直接分派不得产生浏览器、局内状态和可解性三套版本。
- 删除独立狗图导出程序并保留已提交的 SVG 资源。未来只有在真实资源变更 ticket 中同时具备源图、依赖声明、调用说明与可复现检查时，才新增生成器。
- 新匿名用户使用 `crypto.randomUUID()`。持久化或注入 UUID 的校验仍保留，因为存储属于信任边界；只删除过时的生成回退。
- History API 更新省略冗余当前路径参数，让浏览器默认保留当前 URL。
- 删除无用矩形类型、无用可解性转换 helper 和不可能触发的大型旧历史分支。保留损坏存储行为覆盖，并更新或删除仅断言不可达分支名称的测试。
- 将仍在使用的方块入槽转换放入现有暂存槽方块 helper，并由运行时与关卡逻辑共同复用；暂存槽复制也复用同一模块的 clone helper。
- 用标准数组过滤与现有原地更新替代自定义索引删除循环。暂存槽规模有明确上限，无需额外优化层。
- 保留游戏目录抽象、`GameboxApp`、`LevelGenerator`、`GameSession`、`DogItemRuntime`、Worker 准备/回退、回放元数据、不可变已发布关卡及当前动画/音频生命周期。
- 保留用户已有工作区改动，不得回滚、重写或把正在进行的幻化/双生视觉工作混入清理提交。
- 按互相独立的删除领域拆成小型、可审查提交；不为删除的私有或测试专用接口增加兼容别名。

## 测试决策

- 本次工作的好测试应观察具有外部意义的行为：生成关卡相等性、局内状态、DOM 输出、持久化状态、浏览器导航、结果页、命令退出状态或构建产物内容；不应断言已删除 registry、代理文件、wrapper 或路由表存在。
- 最终验收运行 `pnpm test:qa`。由于本次涉及测试基础设施、关卡生成契约、游戏进度与 E2E 行为，不得用 `pnpm test:affected` 代替最终验证，也不要重复运行两层验证。
- 每个逻辑清理批次后运行严格 TypeScript 未使用诊断，确认没有遗留无效 import、参数或声明。
- 验证测试发现结果直接列出所有保留的 Vitest 与 Playwright 测试。对比改动前后的语义测试 case，删除代理入口不得静默降低覆盖。
- 现有生成器与可解性测试继续作为关卡边界、`runSeed` 确定性、种子磁吸选择、冻结结算、双生逻辑单位、乱序事务、难度、回退、回放和 `solutionPath` 有效性的主要 seam。
- 现有 `GameSession` 与道具运行时测试继续作为方块入槽、相邻三消、道具目标、容量、锁槽、机制状态变化、终局状态和复原哨语义的主要 seam。
- 现有 `GameboxApp` 与游戏进度测试继续作为注册、UUID 校验、存储恢复、游戏进度、道具组持久化、导航历史、结果和启动生命周期的主要 seam。
- 现有浏览器流程继续作为注册、进入游戏、执行已验证路径、通关、失败、重试、进入下一关、刷新、离开和重置的最高用户 seam；其中不得保留第二套规则引擎。
- 现有跨浏览器测试继续覆盖 Chromium、WebKit 与移动 Chromium，包括用户并发修改中的幻化/双生视觉，以及已有的减少动态效果行为。
- 原生测试发现和 profile 合并后，只为仍然自定义的 runner 行为保留单元测试；删除只验证已移除 flag 或映射表的测试。
- Pages 构建后验证主 bundle 与关卡生成 Worker 不再包含 QA 专用 profile seed、`run*` 开关或改动文件阈值。这是在验证交付物边界，而不是私有源码形状。
- 删除狗图导出器无需运行时测试；通过现有渲染测试和 Pages 构建确认所有已提交狗图资源仍可访问。
- 验证受支持浏览器中的默认注册可使用原生 UUID 生成，同时无效注入或持久化 UUID 仍按当前公共行为被拒绝或替换。
- 验证损坏和不可用存储仍进入临时运行模式；只删除把已因关卡号越界而拒绝的数据称作“大历史推断”的测试。
- registry 删除后，通过现有公共局内状态/生成器 seam 验证全部五种特殊机制；不再注入自定义机制 handler，因为该不受支持 seam 已删除。
- 在实现 ticket 或最终 QA 记录中登记命令、结果、最终行数变化和依赖变化。约 900 行缩减只是估算，不是验收配额。

## 范围之外

- 改变任何游戏规则、机制预算、难度目标、关卡数量、奖励公式、道具次数、锁槽规则、失败规则或 `runSeed`/回放语义。
- 替换或削弱实际游戏配置、持久化状态、Worker 消息或其他信任边界的运行时校验。
- 删除 Worker 生成、同步回退、预生成、回放校验、不可变已发布关卡或生成诊断。
- 重新设计游戏目录、通用游戏定义、结果契约、`GameboxApp`、`LevelGenerator`、`GameSession` 或 `DogItemRuntime`。
- 在审计指出的重复之外重写求解器、生成器、局内状态、渲染器、动画、CSS 架构、音频、粒子或游戏进度存储。
- 改变当前幻化/双生特殊视觉工作，或在本次清理中重新决定其产品方向。
