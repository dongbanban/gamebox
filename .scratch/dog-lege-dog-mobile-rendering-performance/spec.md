# 狗了个狗移动端动效降载与增量 DOM 渲染

Status: ready-for-agent

## Problem Statement

「狗了个狗」在手机端进入活动关卡后存在持续发热。当前棋盘同时展示大量特殊方块，每个特殊方块可能运行多个无限 CSS 动画；其中整块脉冲会持续改变多层阴影，幻化方块还会同时运行脉冲、遮罩、模糊本体、图像抖动与两层切片效果。即使用户没有操作，浏览器仍需持续进行样式计算、绘制与合成。

当前局内 DOM 更新也放大了点击时的瞬时负载。一次普通方块选择会经历输入锁定和动画完成后的两次视图更新；每次更新都重新生成全部剩余棋盘方块与全部暂存槽。实测在棋盘从 85 个方块减少到 84 个、暂存槽只增加 1 个方块时，浏览器累计移除了 169 个棋盘节点并添加了 168 个棋盘节点，暂存槽节点移除和添加各 14 个。未变化方块也失去原有 DOM 身份，持续动画被重启，并产生不必要的解析、样式与布局工作。

玩家需要在保留特殊机制可识别性、局内规则、输入锁与一次性反馈的前提下，降低静置时的持续负载及点击时的 DOM 抖动。该问题位于具体游戏的原生 DOM/CSS renderer，不应依赖应用 shell 的 Vue 迁移解决。

## Solution

收敛特殊方块的常驻动效。幻化方块保留伪装图案、静态特殊样式、遮罩与模糊本体效果，移除整块脉冲、图像抖动和两层切片效果。棋盘与暂存槽中的其他特殊方块不再运行作用于整个方块或槽位的常驻脉冲、呼吸或闪烁；机制身份改由静态边框、底纹、现有右下角机制标记以及既有状态文案表达。右下角标记可以静态高亮，但不新增无限动画。一次性的飞入、揭示、分裂、吸引、融化、三消、乱序结算、道具及结果反馈保持不变。

将局内后续渲染改为由完整游戏状态驱动的原生增量更新。首次启动仍可一次性创建完整 DOM；之后以稳定方块 ID 对齐当前 DOM 与最新状态，只移除真实离开棋盘或暂存槽的方块，只创建真实新增的方块，并原地同步仍存在方块的可点击状态、目标状态、机制状态与无障碍属性。暂存槽按方块 ID 与槽位顺序增删、移动或更新节点，未变化槽位保持原节点。

保留现有两阶段动画编排与根节点事件委托。输入锁定、结果确认、三消、特殊机制原子结算和道具时序不因增量渲染改变。棋盘尺寸只在首次渲染、视口变化或棋盘几何实际变化时重新适配，不在每次局内状态更新后强制读取布局。

## User Stories

1. 作为移动端玩家，我希望活动关卡静置时减少持续计算，以便长时间游玩时降低发热与耗电。
2. 作为移动端玩家，我希望连续选择方块时页面保持流畅，以便点击反馈不会随着棋盘方块数量增加而变慢。
3. 作为玩家，我希望普通方块不运行无意义的常驻动画，以便视觉注意力集中在真实机制信息上。
4. 作为玩家，我希望幻化方块继续显示本次关卡尝试确定的伪装图案，以便其规则语义保持不变。
5. 作为玩家，我希望幻化方块继续保留遮罩与模糊本体效果，以便移除高负载动画后仍可识别其特殊身份。
6. 作为玩家，我希望幻化方块不再整块脉冲，以便降低动态阴影造成的持续负载。
7. 作为玩家，我希望幻化图像不再持续抖动，以便减少视觉噪声和合成负载。
8. 作为玩家，我希望幻化方块不再显示两层横向切片重影，以便减少裁剪、滤镜与混合模式的持续工作。
9. 作为玩家，我希望幻化方块点击飞行期间仍保持伪装图案，以便优化不提前泄露真实图案。
10. 作为玩家，我希望幻化方块入槽完成后仍按真实图案显现并参与三消，以便规则与反馈时序不变。
11. 作为玩家，我希望检测仪的原位显现反馈继续播放，以便常驻动效精简不删除主动道具反馈。
12. 作为玩家，我希望冻结方块不再通过整个方块的阴影脉冲持续高亮，以便降低棋盘和暂存槽的绘制负载。
13. 作为玩家，我希望冻结方块的静态冻结外观与右下角雪花标记继续可辨认，以便我仍能判断其融化条件。
14. 作为玩家，我希望暂存槽中的冻结进度仍正确更新，以便自然融化规则不受渲染优化影响。
15. 作为玩家，我希望双生方块不再整块脉冲，以便大量双生方块不会持续触发阴影重绘。
16. 作为玩家，我希望双生方块的静态特殊样式与右下角“2”标记继续可见，以便我能预判双倍槽位压力。
17. 作为玩家，我希望双生入槽后的分裂反馈与两个相邻普通方块保持不变，以便性能优化不改变逻辑方块单位语义。
18. 作为玩家，我希望磁吸方块不再整块脉冲，以便其常驻识别不持续消耗绘制资源。
19. 作为玩家，我希望磁吸方块的静态特殊样式与右下角磁铁标记继续可见，以便我能预判吸取行为。
20. 作为玩家，我希望磁吸入槽、目标吸取与后续结算动画保持不变，以便机制过程仍清晰可理解。
21. 作为玩家，我希望乱序方块在棋盘上继续采用普通方块视觉，以便既有隐藏规则保持不变。
22. 作为玩家，我希望乱序方块进入暂存槽后的 armed、triggerable 与 consumed 状态仍可通过静态样式和状态文案识别，以便移除槽位脉冲后不会丢失信息。
23. 作为玩家，我希望复原哨仍只恢复最近一次安全乱序事务，以便视觉优化不改变复原规则。
24. 作为玩家，我希望选择普通方块时只从棋盘移除实际选择的方块，以便其他方块不会被无意义地销毁和重建。
25. 作为玩家，我希望选择后新暴露的下层方块立即获得正确可点击状态，以便增量更新不会留下失效按钮。
26. 作为玩家，我希望输入锁定期间所有不允许操作的方块继续不可点击，以便保留动画事务的原子性。
27. 作为玩家，我希望动画结束后合法方块立即恢复可点击，以便节点复用不会保留过期禁用状态。
28. 作为玩家，我希望暂存槽新增一个方块时只更新受影响槽位，以便其他槽位的视觉和节点状态保持稳定。
29. 作为玩家，我希望三消时只移除组成三消的暂存槽方块并正确收拢剩余方块，以便槽位增量更新符合严格顺序规则。
30. 作为玩家，我希望一次操作产生多组三消时所有对应节点都正确移除，以便增量渲染不遗漏连续区段。
31. 作为玩家，我希望磁吸方块一次移除自身及被吸目标时只更新实际变化的棋盘和暂存槽节点，以便复杂机制不退回全量重建。
32. 作为玩家，我希望双生分裂时只新增两个实际入槽方块，以便未变化槽位保持稳定。
33. 作为玩家，我希望乱序触发时复用相同方块节点并只调整必要顺序，以便重排不会重新创建整个暂存槽。
34. 作为玩家，我希望火把、检测仪与消磁仪改变方块机制状态时只更新对应方块，以便道具反馈仍与目标节点对齐。
35. 作为玩家，我希望道具三消移除、万能方块和容量提升只改变真实受影响的暂存槽节点，以便道具使用不会引发整槽重建。
36. 作为玩家，我希望钥匙解锁时只更新对应锁槽和相关次数，以便其他槽位不被替换。
37. 作为玩家，我希望失败、通关、重试和下一关流程保持不变，以便渲染优化不影响游戏进度与结果。
38. 作为触摸设备用户，我希望 Pointer Events 行为保持不变，以便一次触摸不会重复选择方块。
39. 作为键盘用户，我希望未变化按钮的焦点与可访问状态在更新后保持稳定，以便可以连续操作棋盘和道具。
40. 作为辅助技术用户，我希望按钮语义、ARIA 名称、状态区域与禁用状态继续准确，以便性能优化不牺牲无障碍支持。
41. 作为偏好减少动态效果的用户，我希望所有非必要常驻动画继续被关闭，同时保留静态机制标记，以便系统偏好得到完整尊重。
42. 作为移动端玩家，我希望屏幕旋转、动态视口变化后棋盘仍完整适配可操作区域，以便减少重复尺寸计算不造成布局回归。
43. 作为桌面端玩家，我希望窗口尺寸变化后棋盘仍保持正确缩放与居中，以便移动端优化不破坏桌面布局。
44. 作为维护者，我希望完整游戏状态继续是 DOM 的唯一事实来源，以便增量更新不会产生与规则状态分离的手工补丁。
45. 作为维护者，我希望继续使用稳定方块 ID 对齐节点，以便普通选择、三消和特殊机制共享同一更新策略。
46. 作为维护者，我希望保留现有根节点事件委托，以便节点复用或局部替换不需要逐方块绑定监听器。
47. 作为维护者，我希望不引入虚拟 DOM、状态库或 DOM diff 依赖，以便该性能修复保持小而可维护。
48. 作为维护者，我希望应用 shell 与具体游戏之间的启动和销毁契约保持不变，以便本次优化不耦合 Vue 迁移。
49. 作为维护者，我希望删除失去消费者的动画时长配置、CSS keyframes 与选择器，以便集中配置和样式中不残留无效开关。
50. 作为测试者，我希望通过公开游戏入口执行真实选择与道具操作，以便测试覆盖实际状态、DOM 和动画编排，而不是私有 helper。
51. 作为测试者，我希望未变化节点不会出现在结构性移除或新增记录中，以便全量重建不会悄悄回归。
52. 作为测试者，我希望性能验证使用确定性的节点变化和动画状态作为主要门槛，以便 CI 不依赖易波动的毫秒阈值。
53. 作为发布者，我希望移动 Chromium 与 Safari/WebKit 核心流程继续通过，以便优化在主要移动浏览器中行为一致。
54. 作为发布者，我希望记录优化前后的空闲负载、动画数量和点击 DOM 变化，以便发布决策有可复查证据。

## Implementation Decisions

### 动效范围

- 幻化方块保留伪装图案、静态特殊边框/底纹、遮罩和模糊本体；删除整块脉冲、原图持续抖动以及两层横向切片的持续动画。
- 棋盘与暂存槽中不再存在作用于整个方块或槽位的无限脉冲。冻结、双生、磁吸及乱序槽状态改用静态样式表达；幻化已在上一条中单独定义。
- 右下角机制标记采用静态高亮，不通过 pulse、旋转或其他无限动画强调。复用既有雪花、“2”、磁铁等标记；不为本次工作建立新的图标系统。
- 乱序方块在棋盘上继续使用普通方块视觉。进入暂存槽后保留现有状态属性、状态文案与可区分的静态状态样式，不再让整个槽位持续脉冲。
- 机制说明缩略图与真实棋盘使用相同识别规则：幻化只保留遮罩与模糊本体，双生保留静态“2”标记，其他缩略图不恢复常驻脉冲。
- `prefers-reduced-motion: reduce` 必须关闭剩余的幻化遮罩与模糊本体动画，但保留伪装图案、静态机制边框和标记。
- 飞入暂存槽、幻化揭示、双生分裂、磁吸吸引、冻结融化、三消、钥匙掉落、锁槽解锁、乱序结算、复原、道具反馈、通关和失败等一次性动画不属于本次删除范围。
- Canvas 粒子仍只在一次性反馈期间运行，并在动画结束或游戏销毁时停止。
- 删除不再被任何视图消费的无限动画 keyframes、选择器和自定义属性。若乱序 armed/triggerable 动画时长字段因此没有消费者，同步删除对应集中配置字段、校验与测试数据；不增加替代配置。

### 增量棋盘更新

- 首次启动或进入全新关卡时可以创建完整游戏 DOM；同一关卡尝试内的后续视图更新必须走增量路径。
- 增量路径以最新 `DogLegeDogGameState` 为唯一事实来源，不允许点击处理器直接假设并修改最终 DOM 状态。
- 棋盘按稳定方块 ID 对齐已有节点与 `remainingBlocks`。最新状态中不存在的节点被移除；仍存在且视觉身份未变化的节点必须复用。
- 仍存在的方块原地同步可点击状态、输入锁状态、道具目标状态、ARIA 名称、机制状态属性和必要 class，不因这些属性变化重建节点。
- 方块 ID 保持不变但图案或机制视觉身份实际改变时，只替换该方块节点。典型情况包括火把融化、检测仪显现和消磁仪移除磁性。
- 普通选择只移除所选棋盘方块；磁吸可以同时移除磁吸方块与被吸方块；其他操作按最新状态移除真实缺失的方块，不为不同机制增加平行删除逻辑。
- 棋盘位置与层叠几何在同一关卡尝试内保持由关卡定义决定。增量路径不得重新计算或重写未变化方块的位置样式。
- 新暴露方块的可点击状态必须在同一次状态同步中更新，继续以层叠关系计算结果为准。

### 增量暂存槽更新

- 暂存槽按方块 ID 和最新顺序对齐节点，支持新增、删除、移动及机制状态变化；未变化方块与未变化空槽/锁槽保持原节点。
- 暂存槽容量、有效容量和空闲有效槽位等容器属性继续从最新 session snapshot 同步。
- 容量提升或锁槽解锁可以新增或改变必要槽位，但不得无条件替换全部槽位。
- 三消按结算后的真实方块列表删除对应节点并收拢顺序；同轮多组三消使用同一最终状态同步，不逐组重建暂存槽。
- 双生分裂新增两个独立、相邻且稳定 ID 的普通方块节点；原双生节点不进入暂存槽。
- 幻化入槽完成后创建真实图案的普通暂存槽方块；飞行期间不得用提前创建的真实图案节点泄露结果。
- 磁吸及被吸方块的入槽顺序、保留机制和后续结算继续由 session 决定，renderer 只反映最终 snapshot。
- 乱序调整优先移动既有节点，保持方块 ID 和节点身份；复原哨恢复时同样按恢复后的顺序移动节点。
- 冻结进度变化可以原地更新对应槽内节点；融化改变视觉身份时只替换或更新该节点。

### 渲染与生命周期

- 保留现有游戏启动、开始、读取状态、音效切换和销毁 interface；不增加新的公共 renderer interface。
- 保留输入、反馈、方块动画、道具动画与 loadout controller 当前调用统一 render callback 的结构。两阶段或多阶段调用可以继续存在，但每次调用必须增量同步。
- 保留根节点 Pointer Events 与 click 委托，不给方块或槽位分别绑定监听器。
- 棋盘适配只在首次渲染、窗口/视口 resize 或棋盘几何实际改变时运行。同一关卡中只改变剩余方块、暂存槽或输入锁时不得强制读取棋盘与 frame 尺寸。
- 游戏销毁仍取消活动动画、清理音频和粒子、移除 resize 与输入监听器，并清空游戏内容。
- 现有 `data-*`、test id、ARIA、DOM 层级职责及用户可见文案保持兼容；允许为稳定节点同步增加内部实现所需但不暴露规则的新状态，不增加测试后门。
- 使用原生 DOM API 和现有 renderer 函数完成增量更新。不引入 Vue、第三方 DOM diff、虚拟 DOM、组件库或每个方块一个监听器。
- 暂存槽最多只有少量槽位，可以采用简单线性扫描；棋盘最多 180 个物理对象，按 ID 建表后线性同步足够，不引入通用 reconciliation framework。
- 本 spec 独立于 Vue 3 应用 shell 迁移；未来 shell 切换后，具体游戏仍独占其挂载容器和内部 DOM。

### 文档与决策

- 本决策重新打开 ADR-0006 中“幻化与双生复用 pulse”的具体视觉选择。实现完成时更新该 ADR，说明移动端持续负载证据、被移除的效果以及仍保留的机制识别方式。
- 同步更新领域文档中对幻化、双生和其他机制持续视觉动效的描述。规则、逻辑方块单位、揭示/分裂时序与机制 data attrs 不变。
- v13 集中配置仍是所有剩余可调动画时序的唯一来源；删除动画时同步删除确认无消费者的配置，不创建散落替代常量。

## Testing Decisions

- 最高测试 seam 使用现有公开游戏启动入口。测试挂载真实游戏、执行真实方块选择和道具操作，并观察公开状态、DOM、输入锁及结果；不公开增量 renderer 的私有 helper。
- 好测试验证用户可观察行为和本 spec 明确提出的性能不变量：正确方块被移除、正确槽位被更新、未变化节点未发生结构性替换、剩余动画名称符合约定。测试不锁定内部函数拆分、Map 名称或循环次数。
- 为普通选择增加确定性结构测试：选中 1 个未触发三消的普通方块后，棋盘只移除该方块，其他棋盘节点身份保持；暂存槽只改变目标槽位，其他槽位身份保持。
- 使用 `MutationObserver` 或等价浏览器可观察信号记录棋盘与暂存槽的直接子节点变化。一次状态同步中不得移除并重新添加未变化节点。
- 输入锁阶段和动画结束阶段分别断言按钮禁用/恢复及下层解锁正确，证明节点复用没有保留过期交互状态。
- 为三消覆盖槽内新增、连续三连删除、同轮多组三连与剩余方块收拢；只断言最终顺序和未变化节点保留，不复刻规则算法。
- 复用现有特殊机制 UI/运行时测试覆盖幻化入槽揭示、磁吸自身与目标入槽、双生分裂、冻结进度/融化、乱序重排/复原。新增断言只聚焦受影响 DOM 节点，不改变既有规则断言。
- 复用现有道具测试覆盖火把、检测仪、消磁仪、道具三消移除、万能方块、钥匙和容量提升，验证目标状态、动画时序及局面结果保持一致。
- 为机制视觉增加浏览器样式断言：幻化常驻动画只允许遮罩和模糊本体；棋盘和暂存槽中的其他特殊方块不允许整块无限脉冲；右下角机制标记保持可见且自身不运行无限动画。
- 为机制说明缩略图增加相同视觉契约断言，防止真实棋盘和说明预览再次分叉。
- `prefers-reduced-motion` 测试确认剩余幻化常驻动画关闭，静态伪装图案、边框与机制标记仍存在。
- 不在普通单元测试中设置毫秒级 CPU 或温度硬阈值。CI 以确定性 DOM 变化、动画集合和功能行为为门槛；性能采样作为发布证据记录。
- 使用移动 Chromium 重跑空闲采样，记录总动画数量、renderer/main-thread task time 和浏览器全进程 CPU time；使用相同关卡尝试和采样时长比较前后结果。
- 使用移动 Chromium 重跑普通点击采样，记录棋盘与暂存槽直接子节点添加/移除数，并确认未变化节点保留。
- 跨浏览器 smoke 覆盖 Chromium、移动 Chromium 与 Safari/WebKit 的注册、进入活动关卡、普通选择、至少一种特殊机制和退出流程。
- 响应式验证覆盖竖屏、动态视口和桌面窗口 resize；减少尺寸适配调用后，棋盘和完整暂存槽仍位于可操作视口。
- 纯样式或单一 renderer 阶段优先运行 `pnpm test:ui`，不与 focused/affected 重复叠加。
- 由于最终范围同时涉及 renderer、特殊机制视觉、v13 配置、移动浏览器和游戏运行时集成，功能阶段结束及合并前运行 `pnpm test:qa`、`pnpm test:e2e:cross-browser`、`pnpm build:pages` 与 `git diff --check`。
- 每个实现 ticket 记录实际命令、结果及关联批量 QA；文档-only ticket 可记录未运行测试。

## Out of Scope

- 不把应用 shell、棋盘、方块或暂存槽迁移到 Vue 3。
- 不引入 Pinia、Vue Router、虚拟 DOM、第三方 DOM reconciliation 或游戏框架。
- 不改变关卡生成、runSeed、可解搜索、难度、特殊机制分配或逻辑方块单位。
- 不改变三消、暂存槽容量、锁槽、失败、通关、奖励或游戏进度规则。
- 不改变幻化真实图案与伪装图案的生成、揭示时序或检测仪规则。
- 不改变磁吸目标选择、双生分裂、冻结自然融化、乱序事务或复原哨规则。
- 不删除一次性飞行、三消、机制结算、道具、Canvas 粒子、通关或失败反馈。
- 不重做狗图案 SVG、道具资源、活动游戏整体视觉或响应式布局。
- 不建立新的机制图标设计系统；只复用既有标记与文案，并将其静态高亮。
- 不缓存或持久化局内 DOM、半局状态或动画状态。
- 不把节点身份、内部 Map 或 renderer helper 暴露为生产公共 API。
- 不承诺不同实体手机的固定温度降幅或续航增幅；硬件、浏览器与环境温度差异过大。
- 不在本 spec 中执行 Vue 迁移，也不修改 Vue 渐进迁移的应用 shell 范围。

## Further Notes

- 诊断样例使用移动 Chromium 视口进入首关：85 个棋盘方块中有 22 个特殊方块，共运行 74 个常驻动画。完全停用动画后，8 秒内主线程 task time 从约 1.195 秒降至约 0.003 秒；重复采样方向一致。
- 幻化方块样例有 6 个实例、36 个常驻动画。只移除脉冲与遮罩收益约 4%；移除图像抖动与双切片收益约 18–22%；移除脉冲、图像抖动与双切片并只保留遮罩与模糊本体时，主线程负载下降约 28%。
- 在上述幻化方案基础上关闭冻结、双生、磁吸及槽内乱序的整块 pulse，样例动画数从 74 降至 34；主线程动画 task time 下降约 99%，Chromium renderer、GPU、audio 等全进程 CPU time 合计下降约 59.6%。该实验仍保留了一些非 pulse 合成层效果，因此最终静态标记方案应重新采样，结果可能进一步改善。
- Chromium 采样用于比较代码路径，不等同于实体手机温度；headless 环境的 GPU 实现与移动设备不同。发布结论应表述为持续浏览器负载下降，不把百分比直接换算成温度或续航。
- 普通点击诊断中，棋盘从 85 个方块变为 84 个，实际累计移除 169、添加 168 个棋盘节点；暂存槽累计移除、添加各 14 个节点，证明两阶段渲染均在执行全量 `innerHTML` 更新。
- 目标结构结果是：普通点击只移除 1 个棋盘节点，暂存槽只更新 1 个受影响槽位，两次渲染阶段都保留未变化节点。特殊机制按其真实状态差异增删或移动必要节点。
- 当前根节点已使用事件委托，增量节点复用不需要改变输入绑定策略。
- ADR-0006 当前明确要求幻化和双生复用 pulse；本 spec 以移动端性能证据重新打开并覆盖这一项视觉决策。实现不能只改 CSS 而遗漏 ADR 与领域文档。
- Vue 3 渐进迁移 spec 已把具体游戏棋盘 renderer 列为首轮范围外。本 spec 选择直接优化现有原生 renderer，与该边界一致，也不以 Vue 作为性能前提。
- 发布本 spec 时工作树存在其他特殊机制运行时清理改动。后续实现必须保留用户已有修改，并在开始重叠文件工作前确认最新状态；本 spec 本身不改生产代码。
