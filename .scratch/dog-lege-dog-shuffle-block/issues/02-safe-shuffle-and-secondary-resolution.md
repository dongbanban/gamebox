# 02 — 安全乱序与二次结算

**What to build:** 在 01 的待乱序状态上完成真正的全槽安全乱序。达到由有效容量决定的阈值后，系统基于当前 `runSeed` 生成并筛选候选排列，只执行仍有无道具通关路径的排列；随后自动完成新形成的三消。没有安全候选时保持原序并消耗机制。触发、排列、二次三消与胜负判断作为一次原子操作完成。

**Blocked by:** 01 — 乱序方块入槽与待乱序状态

**Status:** ready-for-agent

- [ ] 触发时保存完整乱序事务状态，生成首版固定数量的去重候选排列，并使用独立于磁吸与钥匙的种子随机流。
- [ ] 触发阈值使用当前有效容量动态计算：有效容量 5、6、7、8 分别对应 3、4、5、5；容量变化后使用新阈值判断。
- [ ] 候选排列操作完整暂存槽方块条目，方块 ID、图案与机制状态始终跟随条目移动。
- [ ] 每个候选经过完整三消、机制状态、容量、终局与无道具可解性验证；只从安全候选中选择结果。
- [ ] 没有安全候选时保持触发前槽序，显示稳定反馈，乱序方块转为已消耗状态，不创建复原快照。
- [ ] 安全排列后自动执行连续相邻同图案三消，正常处理冻结进度、钥匙掉落、容量与胜负状态。
- [ ] 乱序期间锁定冲突输入，二次三消与反馈完成后才开放后续操作。
- [ ] 固定 `runSeed`、相同操作路径与相同生成器版本得到相同候选选择、槽序与结果；记录可供回放的乱序事件。
- [ ] 核心规则、事务边界、失败保护、随机流隔离、槽内反馈与受控关卡测试通过；完成前运行 `pnpm test:qa`。
