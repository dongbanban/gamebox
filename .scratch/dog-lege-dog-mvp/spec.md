# 狗了个狗 MVP

Status: done

> 当前实现以 `.scratch/dog-lege-dog-mvp-hardening/spec.md` 与代码为准。本文件保留 MVP 需求背景；下方涉及棋盘形状、图案阶段、目录卡片与无障碍的旧决策已按当前实现更新。

## Problem Statement

Gamebox 需要验证“浏览器小游戏合集”的第一条完整用户路径：用户进入网页后完成本地注册，浏览游戏目录，进入首个游戏，完成关卡，并在刷新后保留游戏进度与通关奖励。

当前没有后端、真实账号或云同步需求。首个游戏需要复刻堆叠三消的核心体验，同时支持无限关卡、稳定可复现、可解验证与难度筛选，避免随机生成无解棋盘或后期关卡重复失去挑战。

## Solution

构建一个纯前端浏览器小游戏合集。首次访问展示一次点击注册，生成匿名 `userId`；已有 `userId` 时直接进入游戏目录。游戏目录使用静态配置，首个可玩游戏为「狗了个狗」。

「狗了个狗」使用 7 格暂存槽、堆叠方块、三消、通关与失败规则。关卡采用稳定 seed 的无限生成模式：所有关卡使用不规则内部逻辑轮廓与完整长方形可见表面，图案数量、方块数量、层数与层叠布局按关卡进度提升；生成器先构造无道具可解路径，再用难度指标筛选棋盘。首版不启用道具，积分只作为首次通关奖励，不决定解锁。

## User Stories

1. 作为首次访问的匿名访客，我希望点击一次注册按钮即可开始游戏，以便不填写账号资料也能体验合集。
2. 作为首次访问的匿名访客，我希望注册自动生成匿名 `userId`，以便系统能隔离我的游戏进度。
3. 作为回访用户，我希望已有 `userId` 时跳过注册页，以便直接进入游戏目录。
4. 作为用户，我希望自己的身份只存在于当前浏览器，以便 MVP 不引入真实账号、密码与云同步。
5. 作为用户，我希望重置本地数据后回到注册页，以便重新体验首次访问流程。
6. 作为用户，我希望重置前看到确认提示，以便避免误删进度与积分。
7. 作为用户，我希望浏览一个纵向滚动的游戏目录，以便未来容纳多个游戏。
8. 作为用户，我希望看到每个游戏的封面、名称与简介，以便决定进入哪个游戏。
9. 作为用户，我希望在「狗了个狗」卡片上看到最高解锁关卡，以便了解进度；累计积分在通关结果页展示。
10. 作为用户，我希望点击游戏卡片进入游戏，以便开始或继续挑战。
11. 作为用户，我希望“继续游戏”进入当前最高解锁关卡，以便无需手动寻找进度。
12. 作为用户，我希望通过已解锁关卡的启动参数或导航 seam 重玩旧关卡，以便练习旧关卡。
13. 作为用户，我希望未解锁关卡被进度校验拒绝，以便线性解锁规则不被绕过；当前活动游戏页不渲染关卡选择器。
14. 作为用户，我希望完成第 N 关后自动解锁第 N+1 关，以便持续推进无限关卡。
15. 作为用户，我希望局内刷新、返回或关闭页面后重新开始当前关卡，以便系统不保存复杂的半局状态。
16. 作为用户，我希望看到完整长方形可见棋盘中的不规则内部逻辑轮廓，以便关卡布局影响解法，而不是只做背景装饰。
17. 作为用户，我希望逻辑轮廓外没有可玩的方块，以便内部轮廓真正约束摆放。
18. 作为用户，我希望只能点击没有更高层正面积遮挡的方块，以便层叠关系清晰。
19. 作为用户，我希望边缘或角点仅接触不算遮挡，以便方块边界行为稳定。
20. 作为用户，我希望点击方块后方块进入 7 格暂存槽，以便规划三消顺序。
21. 作为用户，我希望三个相同图案类型自动三消，以便无需额外点击确认。
22. 作为用户，我希望六个相同图案类型自动连续消除两组三消，以便完整处理同次操作产生的所有三连。
23. 作为用户，我希望同类方块在暂存槽中相邻排列，以便快速识别槽位压力。
24. 作为用户，我希望暂存槽满且无法继续三消时失败，以便错误选择有明确后果。
25. 作为用户，我希望第七个方块刚好触发三消时不被误判为失败，以便槽位判定符合三消顺序。
26. 作为用户，我希望棋盘方块全部消除后通关，以便获得清晰结果。
27. 作为用户，我希望通关后立即记录进度并解锁下一关，以便动画或页面关闭不丢失结果。
28. 作为首次完成关卡的用户，我希望获得基于关卡难度的积分奖励，以便通关有反馈。
29. 作为重玩旧关的用户，我希望不会重复获得累计积分，以便积分保持意义。
30. 作为用户，我希望通关页显示当前关卡、通关奖励、累计积分、下一关与返回列表操作，以便决定下一步。
31. 作为失败用户，我希望看到当前关卡、重新挑战与返回列表操作，以便快速恢复游戏。
32. 作为用户，我希望离开活动关卡前收到“当前关卡不会保存”的确认，以便避免误离开。
33. 作为用户，我希望看到点击、三消、通关与失败音效，以便获得完整反馈。
34. 作为用户，我希望能静音音效，且刷新后保留静音选择，以便控制环境影响。
35. 作为用户，我希望棋盘在移动端竖屏自动适配，以便不需要滚动、拖拽或缩放即可游玩。
36. 作为桌面端用户，我希望棋盘居中并限制最大宽度，以便大屏幕上仍保持可读性。
37. 作为移动端用户，我希望使用触摸选择方块；作为桌面端用户，我希望使用鼠标选择方块，以便共享同一套交互。
38. 作为用户，我希望游玩中不显示倒计时，以便专注策略而非时间压力。
39. 作为开发者，我希望代码内部统计游玩时长，以便校准 6–8 分钟及后续阶段目标。
40. 作为用户，我希望十种狗主题图案保持稳定，以便形成可记忆的图案类型。
41. 作为用户，我希望游玩中的方块只展示图案、不展示文字，以便保留识别与记忆挑战。
42. 作为维护者，我希望新增游戏只需新增游戏目录项与独立游戏模块，以便合集持续扩展。
43. 作为维护者，我希望公共层不理解具体游戏规则，以便「狗了个狗」不会绑死未来游戏。
44. 作为开发者，我希望同一关在同一生成器版本下始终得到同一棋盘，以便复盘、测试与平衡。
45. 作为开发者，我希望生成器先构造合法消除路径，再反向叠放方块，以便从源头保证至少一条无道具路径。
46. 作为开发者，我希望生成器按难度指标筛选候选棋盘，以便控制不同阶段的体验时长与策略压力。
47. 作为开发者，我希望生成失败时保留 seed、关卡号与生成器版本，以便复现问题。
48. 作为测试者，我希望随机生成每次测试的关卡数量，以便覆盖不同进度组合。
49. 作为测试者，我希望随机测试失败后能用 seed 重放，以便稳定定位问题。
50. 作为测试者，我希望测试覆盖注册、目录、游戏、通关、失败、刷新与重置全流程，以便验证用户可完成完整闭环。
51. 作为维护者，我希望浏览器存储不可用时应用不白屏，以便用户仍能临时游玩并获得明确提示。

## Implementation Decisions

- MVP 是一条垂直闭环：注册、游戏目录、「狗了个狗」、关卡游玩、通关/失败、进度与积分。
- 首版不包含真实认证、多个用户档案、用户切换、退出登录、后端、云同步、排行榜、社交、广告或分享。
- 注册页只提供合集说明与一次点击注册。注册使用浏览器生成的 UUID；不收集姓名、密码、邮箱或验证码。
- 用户模型是单浏览器单用户。已有 `userId` 直接进入游戏目录；重置本地数据删除用户、游戏进度、积分与应用设置。
- 本地状态采用版本化统一结构，至少包含 schema 版本、用户身份、各游戏进度、累计积分与音效设置。局内状态与道具库存不保存。
- 新用户的最高解锁关卡为第 1 关；首次完成第 N 关后，最高解锁关卡至少推进到第 N+1 关；重玩旧关不会降低进度。
- 浏览器存储异常或数据损坏时，应用安全恢复并提示无法持久化；允许临时游玩，不白屏。
- 游戏目录使用静态配置。游戏拥有稳定身份、名称、简介、封面与可玩状态；「狗了个狗」固定排在第一个，新游戏按配置顺序追加，不动态按积分排序。
- 公共层负责注册、目录、导航、公共结果页、用户数据与设置；游戏模块负责自己的规则、棋盘、关卡生成器与动画。
- 渲染采用 Vite、TypeScript、原生 DOM、CSS、SVG 与 Canvas 粒子层。方块使用 DOM/SVG，动画使用 CSS/Web Animations，粒子与彩带等效果使用 Canvas。暂不使用 Cocos、React、Phaser 或其他重型游戏框架。
- 依赖使用 pnpm 管理。
- Vite 与 TypeScript 使用 `@/* → src/*` alias；源码与测试的项目内部 import 使用 `@/...`。
- 「狗了个狗」首关为统一生成器中的稳定起点 profile：不规则内部逻辑轮廓、完整长方形可见棋盘、90 个方块、6 种图案、最多 3 层、固定 seed、目标时长 6–8 分钟、道具不可用。首关与后续关卡共用生成器 pipeline。
- 方块数量阶段为：第 1–5 关 90 个；第 6–10 关 108 个；第 11–15 关 126 个；第 16–20 关 144 个；第 21–25 关 162 个；第 26 关起 180 个。方块数量封顶，不无限增加。
- 最大层数阶段为：第 1–5 关 3 层；第 6–15 关 4 层；第 16–30 关 5 层；第 31 关起 6 层。
- 所有关卡的内部逻辑轮廓均为不规则模板；可见棋盘表面统一为完整长方形。模板使用稳定的 playable mask 约束合法摆放，不通过可见 clip-path 裁切棋盘。
- 形状模板使用方块锚点细网格定义。每个方块占 `4×4` 个逻辑细格，`x/y/z` 为整数，方块不旋转；每个方块完整落在内部逻辑轮廓内。
- 同一层方块不得正面积重叠；不同层可以重叠。仅边或角接触不算重叠。任意更高层活动方块与下方方块有正面积重叠时，下方方块不可点击。单个下方方块最多被 4 个上层方块遮挡。
- 首发图案池固定为：打工狗、单身狗、舔狗、看门狗、疯狗、拆家狗、龇牙狗、社恐狗、吃货狗、傻狗。使用统一风格 SVG 插画；图案类型与图片资产分离，后续可替换图片。
- 图案类型按阶段从 10 种中无重复选择：第 1–5 关 6 种、第 6–15 关 8 种、第 16 关起 10 种。每种图案在整关的总数量必须是 3 的倍数；局部区域内可任意分布。
- 图案生成先形成 `方块总数 / 3` 个三连组，再将三连组交错到合法消除路径中。此规则允许同一图案在整关出现多组三连，同时避免全局产生无法配对的余数。
- 暂存槽固定 7 个位置。点击后，同类方块插入已有同类后方；新图案插入末尾。插入后处理所有完整三连，直到没有可处理三连；处理后棋盘为空则通关，否则暂存槽满且无法继续消除则失败。
- 点击成功后，方块立即从逻辑棋盘移除并播放飞入暂存槽动画。动画期间锁定输入；动画完成后开放下一次操作。动画只负责视觉，胜负由游戏状态决定。
- 通关在逻辑状态确认后立即写入进度、首次通关奖励与下一关解锁，再播放结果动画。重复进入结果页不重复奖励。
- 进入游戏默认打开当前最高解锁关卡；已解锁关卡可通过启动参数或导航 seam 重玩，未解锁关卡由进度校验拒绝。活动游戏页不渲染关卡选择器；返回列表、浏览器后退或刷新不保存半局，活动关卡离开前显示确认提示。
- 「狗了个狗」首版不启用道具。道具保留为未来扩展概念，只在当前关卡使用，不跨关卡形成库存。
- 默认生产关卡由稳定游戏身份、默认 seed、生成器版本与关卡号决定，不使用 `userId` 或当前时间；显式生成请求还会使用 `testSeed` 驱动候选重试。修改生成算法时提升生成器版本。
- 生成器先构造至少一条无道具通关路径，再反向叠放方块并回放验证。每个候选棋盘计算方块数量、最大层数、遮挡率、安全选择数量、暂存槽峰值压力、形状复杂度与图案种类数量等难度指标。
- 安全选择目标随阶段变化：前期至少 3 个，中期通常至少 2 个，后期允许 1–2 个，极少数高难关允许唯一关键路径。
- 目标时长为阶段区间：第 1–5 关 6–8 分钟；第 6–15 关 7–9 分钟；第 16–30 关 8–10 分钟；第 31 关起 8–12 分钟。目标针对中等玩家，不设置硬倒计时。
- 生成器最多尝试固定次数寻找符合难度区间的候选。若没有完全命中，优先选择仍然可解且最接近目标的候选，必要时逐步放宽难度区间，不返回无解棋盘或白屏。
- 积分只作为「狗了个狗」首次通关奖励，按关卡难度计算，不按用时计算，不作为解锁条件。具体分值与公式保留为可配置决策。
- 音效包含点击、三消、通关与失败反馈；音效默认开启，进入活动游戏时沿启动点击链初始化并尝试播放，首次方块操作可重试被浏览器拒绝的播放，静音设置持久化。
- 移动端以竖屏为主，棋盘自动缩放，不支持棋盘滚动、拖拽或缩放；桌面端居中并限制最大宽度。输入统一使用 Pointer Events，覆盖鼠标与触摸。
- 结果页不展示本局用时或内部难度分；代码内部保留时长与难度统计用于调试。方块游玩中不展示狗名称文字。
- 应用不承诺完整专项无障碍适配（如系统化键盘流程、读屏覆盖、减弱动画与色彩无障碍方案）；当前交互按钮、返回/音效控制与即时反馈保留基础 ARIA 语义。

## Testing Decisions

- 测试只验证公开行为，不验证私有函数、内部数组结构、模块调用次数或动画每一帧。明确公开的布局契约（如 `48px` 方块基准、逻辑坐标映射、视口内完整可操作）可以验证；测试名称描述用户可观察行为。
- 核心测试 seam 是 `GameSession`。通过启动、选择方块与读取快照观察可点击方块、暂存槽、三消、通关、失败、输入锁与通关奖励。
- 关卡生成测试 seam 是 `LevelGenerator`。通过关卡号、base seed、test seed 与生成器版本取得关卡结果，验证方块数量、图案总数、逻辑轮廓合法性、同层重叠、遮挡上限、可解路径、安全选择与难度区间。
- 持久化测试 seam 是 `ProgressStore`。通过读取、首次完成记录与重置观察用户生成、已有用户跳过注册、进度保存、首次奖励幂等、多游戏隔离、刷新恢复、损坏数据恢复与存储异常降级。
- 应用端到端 seam 是公共用户流程。使用真实浏览器操作注册、进入目录、进入「狗了个狗」、通关、失败、返回列表、刷新与重置；不把端到端测试扩展为所有内部规则的重复测试。
- 使用 Vitest 做 `GameSession`、`LevelGenerator`、`ProgressStore` 的单元与集成测试；使用 Playwright 做注册、目录、游戏结果与跨浏览器端到端测试。Playwright 默认覆盖 Chromium；跨浏览器 smoke 覆盖 Safari（Playwright WebKit）与移动 Chromium。
- 生成器使用属性/不变量测试。每次运行按 `testSeed` 确定性选择 1–100 个连续前缀关卡；固定覆盖第 1、5、10、15、30、100 关；另设 100–1000 个关卡的压力测试。
- 随机测试记录 `testSeed`、关卡号、关卡 seed 与生成器版本。默认 test seed 为固定值，环境变量可覆盖；失败案例可使用记录的 seed 单独重放，不依赖不可控的随机源。
- 测试覆盖全场景：首次注册、回访、重置、存储不可用、损坏数据、三消、多个三连、槽位临界、失败、通关、重复通关、刷新、返回、浏览器后退、音效设置、难度筛选降级与生成器异常。
- 动画测试只验证输入锁、状态最终一致、下层解锁、通关/失败结果出现；不验证具体帧率、像素位置或 CSS 实现。关键视觉效果通过人工视觉 QA。
- 测试 seam、命名与断言以 `CONTEXT.md` 中的领域语言为准；当前仓库已有业务代码与测试，新增测试继续验证公开行为。
- 当前 `test:core` 会误收集 `tests/e2e/**`，`test:affected` 仍匹配目录整理前的生成器路径；修复与最终全量门禁由新 feature effort ticket 11 跟踪，旧 hardening ticket 19 已归档。

## Out of Scope

- 真实注册、登录、密码、邮箱、验证码、账号找回与多用户切换。
- 后端、云同步、数据库、排行榜、社交、广告、分享与在线运营系统。
- 「狗了个狗」道具效果、道具数量、道具动画、道具消耗与道具库存。
- 其他游戏的实现与专属积分规则。
- 倒计时、速度奖励、时间惩罚、体力、生命与强制刷关。
- 棋盘拖拽、平移、缩放、页面内横向操作与 3D 视角。
- 完整键盘/读屏覆盖、减弱动画与专项色彩无障碍适配；基础按钮与状态 ARIA 语义属于当前实现。
- 写实狗图片、额外品牌美术与第三方运行时音效素材；当前使用项目内狗主题 SVG 与本地 CC0 音乐、程序化交互音效。
- Cocos、React、Phaser、Pixi 等重型游戏引擎或 UI 框架。

## Further Notes

- 6–8 分钟及后续时长是中等玩家目标区间，不是硬限制。实际试玩数据应反馈给难度筛选权重与生成器配置。
- 「狗了个狗」的不规则内部逻辑轮廓、完整长方形可见棋盘、十种图案类型、90–180 方块曲线、稳定 seed、无道具可解路径与安全选择规则属于当前冻结范围。
- 道具与积分数值是明确的后续决策，不应阻塞首版无道具核心闭环。
- 任何改变游戏进度、生成器可解性、暂存槽规则、渲染方式或测试 seam 的实现，应先更新本 spec 与领域术语，再进入实现。
