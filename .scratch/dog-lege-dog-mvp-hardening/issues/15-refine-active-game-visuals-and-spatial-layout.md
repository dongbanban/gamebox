## Implementation Notes

- 使用与当前棋盘相同的方块渲染语义渲染暂存槽，区分“空槽”和“已放入方块”，不复制一套低对比占位卡片样式。
- 顶部控制布局只改变活动游戏页 UI；游戏目录仍可展示游戏名称，历史关卡启动与游戏进度模型不因移除关卡选择 DOM 而删除。
- 区域可以按棋盘逻辑坐标划分为中心区与四角区。中心区需要占多数，四角区保持少量；不要用固定等量或规则网格重新制造紧凑方阵。
- 在既有合法消除路径/候选摆放之后加入区域分布约束。候选失败时做确定性重试或 fallback，不降低 `1/4`/`1/2` 重叠、同层不重叠、遮挡上限或可解性硬约束。
- 区域内层叠与跨区层叠均基于正面积交集；边/角接触不算遮挡。测试 oracle 独立计算区域归属与交集。
- 文件结构按三层职责整理，建议保持以下布局：

  ```text
  src/games/dog-lege-dog/
  ├── index.ts
  ├── assets/
  ├── game/
  └── levels/
  ```

  `assets/` 只放图案、音效与动画资源；`game/` 只放局内状态、控制器、渲染器与游戏配置；`levels/` 只放关卡类型、生成、摆放、规则、难度、回放与奖励逻辑。不要为单个文件继续创建更深层目录。
- 移动文件后优先统一 import 路径与 barrel/entry 导出，再运行类型检查；不通过复制旧文件或保留两份实现兼容旧路径。
