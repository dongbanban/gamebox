# 07 — 修复安全选择三态搜索与难度筛选

**What to build:** 让安全选择验证区分“可解”“不可解”“搜索预算不足”，避免固定小预算把真实安全选择误判为不可解，并保证难度筛选使用可信指标。

**Blocked by:** 02 — 共享层叠关系图并收敛局内快照；06 — 扩展全部无限不规则关卡

**Status:** done

- [x] 可解搜索返回 `solvable`、`unsolvable`、`budget-exhausted` 三种结果。
- [x] 只有完整证明失败才能返回不可解；预算耗尽不能转换为不可解。
- [x] 搜索预算至少允许一条覆盖全部剩余方块的首选续解路径被验证。
- [x] 分支预算与路径深度分别管理，不再使用固定 16 个总访问状态限制完整路径。
- [x] 安全选择只统计已经证明存在无道具续解路径的选择。
- [x] 存在预算不足时，候选难度标记为不确定且不能作为命中目标的候选。
- [x] 难度 fallback 可以放宽目标区间，但不能返回无解关卡或绕过几何硬约束。
- [x] 测试覆盖超过 16 个剩余方块、原顺序失败但存在替代合法续解路径的案例。
- [x] 同一关卡、seed 与版本继续产生稳定难度与重放信息。

## Comments

- `findSolvability` 暴露三态结果；旧 path/boolean API 保留为兼容层，只报告已证明可解。
- 搜索分支预算、路径深度分离；首选续解路径不消耗分支预算；完成状态做确定性 memo。
- 安全选择只计入已证明续解；任一候选搜索预算耗尽 -> 难度 `uncertain`，不能命中目标。
- 默认难度筛选在一次放宽目标窗口后使用最近的已证明候选；候选仍通过几何校验与可解校验。
- 验证：`pnpm typecheck`；`pnpm build`；`pnpm test:core`（60 tests）；`DOG_RANDOM_LEVEL_COUNT=1 DOG_STRESS_LEVEL_COUNT=100 pnpm test:random`（3 tests）；`pnpm test:e2e`（12 tests）。
