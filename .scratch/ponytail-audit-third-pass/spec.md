# Ponytail：第三轮仓库精简与历史清理

Status: ready-for-agent

## 问题陈述

Gamebox 已完成「狗了个狗」MVP、v13 机制扩展、乱序方块、两轮 Ponytail 清理和移动端渲染优化，但仓库仍保留了多类不会增加当前用户价值的维护面。

本地 issue tracker 中保留了约 3,900 行已经完成、被后续决策覆盖或尚未获批的规格与 ticket 记录；其中多份顶层规格仍标记为 `ready-for-agent`，与对应验收项已经完成、代码已经合并的事实不一致。未获批的 Vue 迁移规格还预先设计了并行 shell、适配层、共享契约和新增依赖，当前没有已接受的迁移需求。

v13 集中配置来自仓内 TypeScript 常量，却被当作运行时不可信输入处理。配置加载层维护约 840 行手写 schema 校验、错误聚合和深度复制，并配套约 160 行只验证无效注入配置的测试。生产环境没有远程配置、用户配置或持久化配置入口；主线程与 Worker 之间传递的仍是同一个受编译约束的仓内配置。该结构重复了 TypeScript 已经提供的静态检查，并扩大了应用启动、游戏启动和关卡生成的契约。

测试 profile 的执行顺序固定，但当前仍通过三百余行计划构造、报告格式化和命令执行代码表达，并使用一百余行单元测试验证这份固定命令表。具体命令本身已经由包管理脚本、Vitest、Playwright、Git 与 shell 提供。

「狗了个狗」公共入口继续转发大量内部类型、常量和 helper，实际生产消费者只需要关卡准备服务和游戏启动函数。道具运行时仍允许注入自定义道具定义和次数函数，但仓内生产只存在固定的八种道具；该扩展点只被合成测试使用。局内动作结果同时把完整快照展开在结果根部并再次暴露为 `snapshot`，乱序运行时通过一个只有单一生产者的十余字段 adapter 访问局内状态。

此外，仓库还保留了一次性移动端性能采样程序、四个只做转发的关卡进度 helper、手写的关卡尝试种子生成器、一个零消费者校验函数和重复的特殊机制移除实现。这些内容分别可以由删除、现有 helper、TypeScript 类型、包管理脚本或浏览器原生能力替代。

这些维护面不会直接造成用户可见错误，但会增加代码导航成本、公共名称数量、测试维护成本和后续变更的同步点，也会让已经完成或未获批的工作继续看起来像活动需求。第三轮审计估计可净删约 5,800 行，不删除依赖。

## 解决方案

执行一次以删除、收窄和复用为主的第三轮仓库精简。在不改变「狗了个狗」玩法、关卡生成、可解性、难度、游戏进度、动画、音效、移动端增量渲染和跨浏览器行为的前提下，只保留当前真实消费者需要的契约与工具。

清理已完成或已被覆盖的本地规格与 ticket 记录，删除未获批的 Vue 迁移计划，并同步收敛仍指向旧 ticket 的代理文档。Git 历史继续承担历史实现记录，ADR 与根领域文档继续承担当前有效决策；当前第三轮精简规格在实现期间保留为活动工作入口。

将 v13 配置恢复为编译期类型约束的仓内常量：配置源继续使用完整 `DogV13Config` 类型并在创建时深度冻结，但不再维护面向任意 `unknown` 输入的运行时 schema 解释器。需要注入替代配置的仓内测试使用类型正确的配置对象。持久化数据、关卡生成请求、用户操作与其他真实信任边界的校验保持不变。

固定的 smoke/full QA 流程使用包管理脚本和 shell 原生 fail-fast 编排；保留现有 profile 名称、测试范围、seed、受影响文件分类、构建、diff 和文件行数守卫，不再为静态命令表建立计划对象和专属测试层。

收窄「狗了个狗」公共入口，只暴露游戏目录真实使用的启动能力；测试改为从负责行为的模块直接导入。保留 Gamebox 的通用游戏目录、游戏定义、启动、结果和进度契约，不把应用改写成单游戏特例。

道具运行时直接消费固定的内置道具行为，移除仅供测试注入的自定义定义、次数函数和归一化 adapter。局内动作结果只保留一份完整快照。乱序运行时直接消费现有局内状态对象，关卡进度调用方直接使用 v13 配置 helper，关卡尝试种子直接使用 `crypto.randomUUID()`。删除一次性采样程序、零消费者 helper 和重复转换。

## 实现决策

- 本次只做删除、收窄、直接复用和原生能力替换。不新增依赖、框架、工厂、registry、兼容层或替代测试系统。
- 历史清理覆盖已经完成、已经被后续决策覆盖或没有未完成验收项的旧 feature effort。删除前以当前代码、提交历史和 ticket 勾选状态确认其不再是活动工作。
- 当前第三轮精简 effort 在实现期间保留。未来完成后的归档方式不在本次实现中自动推断。
- 删除未获批的 Vue 迁移规格。若未来确有框架迁移需求，基于届时应用 shell、性能证据与产品需求重新建立规格，不复用当前推测性并行实现计划。
- 当前有效的领域语言继续由根领域文档维护；仍具约束力的架构决策继续由 ADR 维护。代理说明、README 和领域文档中指向已删除 ticket 的导航文字同步改为当前事实。
- v13 配置源继续由完整 `DogV13Config` 类型约束，并在模块初始化时只创建、复制和深度冻结一次。不得用宽泛断言绕过配置类型。
- 删除面向任意 `unknown` 配置对象的字段遍历、错误列表、schema 错误类和分区校验模块。应用、游戏启动、关卡生成与准备服务不再重复加载同一仓内配置。
- 可选配置注入如果仍被真实仓内测试需要，参数类型收窄为 `DogV13Config`；测试通过类型正确的对象覆盖少量动画、音频、暂存槽或道具值。不得保留专门验证畸形测试配置的运行时分支。
- 保留配置 helper 对关卡号、逻辑方块数、暂存槽容量等函数参数的局部前置条件检查，因为这些值来自运行时调用而不是静态配置声明。
- 保留持久化状态 normalization、UUID 校验、关卡请求与回放校验、道具目标校验、局内状态转换保护、Worker 生命周期错误处理和所有避免数据丢失的异常处理。
- 本决策明确重开 ADR-0007 中“配置进入游戏启动和生成器边界时执行完整运行时校验”的部分。实现必须同步更新 ADR，说明仓内静态配置改由 TypeScript 与一次性冻结保证；ADR 中关于集中配置是唯一行为来源的决策继续有效。
- smoke 与 full 的命令序列改由现有包管理脚本和 shell fail-fast 表达。保留当前核心测试、Worker fallback、随机回归、Chromium、跨浏览器、Pages 构建、diff 与文件行数检查范围。
- 测试 profile 数据只保留真实消费者使用的关卡、seed 和压力参数。删除重复 profile 名称、永远不会产生的分类值、静态计划对象、报告对象和只验证固定命令数组的测试。
- 受影响验证继续使用 Git 获取改动文件、Vitest `related` import graph 选择核心测试，并按现有高风险规则升级 smoke 或 full。若分类逻辑仍需要自定义代码，只保留这一处决策逻辑。
- 「狗了个狗」入口仅转发游戏目录生产消费者所需的关卡准备服务和游戏启动能力。测试与内部模块从行为所属模块直接导入类型、常量和 helper。
- 游戏目录的通用 `GameDefinition`、准备、启动、结果、游戏进度和多游戏集合结构继续保留。本次不以当前只有一个游戏为由删除 Gamebox 的核心产品边界。
- 目录模块不再重复转发通用游戏契约；应用与测试直接依赖通用契约模块。
- 删除一次性移动端性能采样程序。已经提交的性能证据保留在提交历史和已生效的 ADR/领域决策中；未来性能问题使用当时可复现的最小测量重新建立工具。
- 道具运行时不再接受自定义运行时定义集合或每道具次数函数。固定八种道具继续通过现有内置行为表直接分派，次数直接来自 v13 配置 helper，钥匙继续使用锁槽上限与掉落规则。
- 删除仅服务合成道具测试的 definition 类型、fixture、归一化 adapter 和不可达分支。可由真实内置道具触发的提交失败或动画后失效行为继续通过公开运行时操作覆盖。
- 局内动作结果统一为动作元数据加单个 `snapshot`。不再把 `GameSessionSnapshot` 展开到结果根部；控制器、道具行为和测试统一读取 `snapshot` 中的局面状态。
- 乱序运行时直接接收现有局内状态实例，读取公开的包内状态和方法。删除单一实现的 context interface 及构造阶段 getter/setter 转发，不新增第二个状态接口。
- 删除关卡进度纯转发模块。调用方直接使用 v13 的关卡阶段、逻辑方块数和难度目标 helper；不建立兼容别名。
- `createRunSeed` 直接使用 `crypto.randomUUID()`。当前匿名用户身份已经无条件依赖同一原生能力，因此不保留更低浏览器基线的 fallback。
- 特殊机制移除复用一份现有方块转换实现；棋盘方块和暂存槽方块不再分别维护等价的对象解构函数。
- 删除零消费者校验函数和仅为旧公共入口存在的导出修饰。严格 TypeScript 未使用诊断应在清理后保持无错误。
- 约 5,800 行缩减是审计估算，不是验收配额。不得为了达到估算删除真实行为、降低验证强度或增加难懂的一行式实现。
- 按历史资料、配置、测试 runner、公共入口、道具运行时、局内结果/乱序、原生小项和最终文档验收分批实施。每批保持可审查，且不覆盖用户并发改动。

## 测试决策

- 好测试观察用户可见行为、稳定公共状态、持久化结果、生成关卡、浏览器导航或命令退出状态；不锁定 import 路径、私有 class、计划对象、adapter 字段、文件数量或已删除 helper。
- 最高用户 seam 使用现有 Playwright 浏览器流程，覆盖注册、游戏目录、开始关卡、加载、道具组、游玩、通关、失败、重试、下一关、返回、刷新与离开保护。不新增生产调试入口。
- 应用级行为继续通过现有 `mountApp` seam 覆盖自定义目录、内存 storage、损坏 storage、游戏启动、预生成、结果确认、进度写入、音效同步、History State 和销毁。
- 具体游戏行为继续通过现有游戏启动 seam 验证 DOM、输入锁、动画、音效、粒子、增量棋盘和增量暂存槽；不测试协调器的私有调用次数。
- 局内规则继续通过 `GameSession` 的公开方法与快照验证可点击条件、入槽、三消、锁槽、容量、特殊机制、乱序事务、通关和失败。动作结果改为单快照后，断言统一读取该快照。
- 道具行为继续通过 `DogItemRuntime` 与真实八种内置道具验证次数、可用状态、目标选择、取消、动画提交、原子失败、钥匙掉落和复原哨。删除只证明自定义 definition 可注入的测试。
- 关卡生成继续通过 `LevelGenerator` 与现有生成器测试覆盖关卡边界、逻辑方块单位、形状、机制分配、难度、可解性、fallback、回放和 `runSeed` 确定性。
- v13 配置测试保留配置中真实行为值、helper 边界和模块初始化不可变性的断言；删除只向仓内静态配置注入畸形对象并期待 schema 错误列表的断言。
- 配置类型正确性由 TypeScript 构建检查承担。不能用运行时测试重复证明编译器已经证明的字段存在性和类型关系。
- 测试 runner 精简后，通过实际执行 `focused`、`smoke` 与 `full` 入口验证退出状态和覆盖范围。静态命令链不再建立镜像计划对象单元测试。
- 保留受影响文件分类中真正存在的决策测试，重点验证 UI-only、随机回归和高风险改动分别选择正确范围；删除只验证固定步骤名称和字符串拼接的断言。
- 删除历史 `.scratch` 内容、Vue 迁移规格和一次性性能采样程序不新增运行时测试；通过 Git diff、文档引用搜索和现有完整 QA 确认没有活动入口依赖它们。
- 公共入口收窄后，确认生产构建和测试不再通过宽 barrel 获取内部符号；测试收集数量与语义用例不得因 import 重写而静默下降。
- 原生 UUID 替换继续通过关卡尝试唯一性、相同显式 `runSeed` 的确定性和真实浏览器启动流程验证；不测试 UUID 实现内部格式之外的随机性质量。
- 清理完成后运行严格未使用诊断，确认没有遗留无效 import、参数、声明和零消费者导出。
- 本次横跨公共契约、游戏启动、生成器配置、运行时与测试基础设施，最终验收直接运行一次 `pnpm test:qa`，不要先运行或叠加 `pnpm test:affected`。该 profile 已包含核心测试、随机回归、浏览器流程、跨浏览器、Pages 构建、diff 和文件行数检查。
- 每个实现批次按影响范围运行最小可用检查；最终 ticket 记录实际命令、通过结果、测试收集变化、净删行数和依赖变化，并关联此前批次。

## 范围之外

- 不改变任何用户可见游戏规则、关卡数量、逻辑方块增长、机制预算、难度目标、奖励公式、暂存槽容量、锁槽规则、道具次数或失败条件。
- 不改变 `runSeed` 在关卡尝试、失败换组、重试、重玩、下一关、回放或预生成中的生命周期语义。
- 不重写关卡生成器、可解性搜索、难度计算、乱序算法、特殊机制分派、游戏进度 schema 或 Worker fallback。
- 不删除或削弱持久化数据、用户输入、回放请求、关卡号、道具目标和局内操作等真实信任边界的校验。
- 不删除 Gamebox 的通用游戏目录、游戏定义、准备、启动、结果或多游戏进度契约。
- 不迁移到 Vue、React 或其他 UI 框架，不新增状态库、路由库、schema 库、测试框架或构建依赖。
- 不重新设计应用 shell、游戏页面、动画、音效、粒子、CSS、SVG、响应式布局、无障碍语义或移动端增量渲染。
- 不以删除测试行数为目标降低关卡生成、特殊机制、道具、进度、浏览器或跨浏览器覆盖。
- 不删除当前第三轮精简规格或任何实现期间新建且仍处于活动状态的 ticket。
- 不处理本次扫描之外的正确性、安全性或性能问题；这些问题应进入普通 review 或独立规格。
- 不删除、升级或替换现有 npm 依赖；当前审计未发现可删除依赖。

## 进一步说明

- 本规格来自第三轮 repo-wide Ponytail 审计，列出的是可删除复杂度，不是用户功能重做。
- 第一轮与第二轮 Ponytail 清理已经分别处理 v13 死代码、独立 E2E 求解器、测试代理发现、特殊机制 registry、一次性图标导出器和部分测试 runner；本轮只处理当前仓库仍然存在的维护面。
- 配置校验收缩与 ADR-0007 当前要求完整运行时校验的部分冲突。实现前或同一批次必须更新该 ADR，不能让文档继续宣称不存在的 schema 边界；集中配置作为唯一行为来源的核心决策不变。
- 历史 issue tracker 清理需要同步移除代理文档中对旧 ticket 编号、旧 profile 实现和已归档 hardening 入口的引用。当前有效领域规则应落在领域文档或 ADR，而不是通过保留全部 ticket 来间接维护。
- 「约 5,800 行、0 个依赖」是当前审计估算。实现完成后以实际 Git diff 重新计算并记录，允许因保留真实行为而低于估算。
- 仓库当前工作树在规格发布前为干净状态；实现代理仍必须在每个批次前检查并保留之后出现的用户改动。
