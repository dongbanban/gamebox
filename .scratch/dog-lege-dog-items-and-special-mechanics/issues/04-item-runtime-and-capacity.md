# 04 — 道具执行框架与暂存槽容量提升

**What to build:** 为游戏提供道具运行时；统一处理道具次数、目标选择、取消、原子结算、输入锁定，并落地暂存槽容量提升道具。

**Blocked by:** 01 — 道具次数与执行必须绑定关卡尝试；02 — 执行框架必须读取已确认道具组。

**Status:** done

- [x] 道具定义、目标类型、使用次数、执行效果及视觉反馈由具体游戏注册；公共层不理解具体道具效果。
- [x] 每种已选道具独立配置本关使用次数，基础方案为每关 1–2 次；次数为 0、道具未选或当前状态不允许时，道具不可用。
- [x] 目标型道具进入目标选择后允许取消；确认前取消不改变棋盘、暂存槽和次数。
- [x] 无目标道具点击后直接执行，不显示目标确认；有目标道具确认后原子执行，成功才扣 1 次。
- [x] 无效目标、找不到合法补充方案、执行被取消、次数为 0、关卡已结束均不扣次数；道具效果不会造成通关失败，失败已确认后不能被道具挽救。
- [x] 道具选择、目标选择、道具动画、三消动画及结算期间锁定冲突的普通点击与其他道具输入；每次状态变化后重新计算可用性。
- [x] 道具动作不可撤销；成功执行后只能继续当前状态。
- [x] 暂存槽容量提升为无目标道具，成功使用后当前尝试容量 `+1`，每关最多 1 次；不影响后续关卡基础容量。
- [x] 重开、重试、进入新关或尝试被重置后，容量加成清除；道具面板显示剩余次数与不可用状态。
- [x] 增加运行时、次数扣除、取消、输入锁、容量生命周期及 UI 测试。
