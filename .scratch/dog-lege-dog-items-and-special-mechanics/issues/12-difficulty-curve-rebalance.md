# 12 — 难度曲线与前期关卡重平衡

**What to build:** [历史实现] 基于真实生成数据重做「狗了个狗」难度目标，让第 1 关起具备可玩的挑战梯度，减少前期连续简单关卡，同时保持每关可解与现有奖励公式。

**Blocked by:** 10 — 多特殊机制组合与难度/次数校验必须先提供完整机制难度输入。

**Status:** done
## V13 迁移状态
本票完成 v10 难度基线，状态保持 done，不重开。v10 样本与验证结果保留为历史对照；用户确认的更高压力目标、安全选择率、预计时长与 30% 机制密度统一迁移到 ticket 20。

## Historical v10 acceptance (superseded)
- [x] 先用固定测试种子批量生成当前关卡，记录第 1–30 关的 `safeChoiceCount`、预计时长、方块数、层数、图案数、遮挡/重叠、特殊机制密度及求解路径指标，形成可比较的难度基线。
- [x] 建立按关卡号或阶段变化的明确难度目标曲线；相邻阶段目标必须整体变难，不能继续让多个前期阶段共用同一宽松目标。
- [x] 第 1 关保持可进入、可学习，但不再使用近乎纯教学的简单配置；前 1–5 关应出现可观测的递进差异，不得批量落入同一低难度档。
- [x] 难度目标同时约束安全选择空间与预计时长，并结合方块数、层数、图案数、遮挡/重叠及特殊机制实际影响；不得只增加方块数量或只压低奖励来制造表面难度。
- [x] 对容易生成简单局面的指标设置有效上限；不再用无限上界让明显低压候选通过前期难度验证。
- [x] 随机候选允许同一关不同 `runSeed` 有自然波动，但批量分布必须落在该关目标范围，关卡号提高后难度均值与目标下限不得回退到前一阶段。
- [x] 生成失败或 fallback 时仍必须满足当前阶段的难度下限、无道具可解性及预计时长约束；不得通过静默放宽目标把简单候选当作成功结果。
- [x] 难度计算完整模拟冻结自然融化、幻化点击揭示、暂存槽限制及其他已启用机制；道具只是捷径，不得把必须使用道具作为提高难度的手段。
- [x] 现有奖励公式保持不变，继续使用重平衡后的生成难度指标；不通过修改奖励公式掩盖难度曲线问题。
- [x] 增加难度目标曲线、阶段边界、前 1–30 关批量分布、固定 seed 回归、不同 seed 波动、fallback、回放及无道具可解性测试。
- [x] 记录重平衡前后指标对比与实际验证命令；生成器/跨模块验证使用 `pnpm test:qa`。
