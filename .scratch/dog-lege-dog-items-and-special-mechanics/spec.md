# 「狗了个狗」道具与随机特殊机制

Status: ready-for-agent

## Problem Statement

当前「狗了个狗」只有基础堆叠三消玩法：固定暂存槽、普通方块、确定性关卡与通关/失败流程。游戏缺少局内道具、特殊方块与可扩展的关卡规则，无法提供不同关卡的策略变化。

当前第 1 关仍有固有关卡入口，关卡生成主要依赖稳定输入；重开或重试无法形成新的棋盘体验。加入随机棋盘后，若没有完整的 `runSeed`、生成前可解性验证与回放能力，玩家可能遇到无解局面，开发者也无法复现问题。

道具、特殊方块、关卡生成与公共进度还需要保持边界：不同游戏可以拥有不同道具；局内次数不能变成跨关库存；换道具组不能意外回滚已确认进度；特殊机制不能破坏“至少存在一条无道具通关路径”的核心承诺。

## Solution

为游戏提供游戏自有的道具系统与可扩展特殊机制系统。「狗了个狗」首版使用固定 7 种道具，用户首次进入游戏时从中选择 3 种不同道具；道具组跨关卡顺延，次数按关卡配置重新初始化。新增消磁仪与钥匙；钥匙是常规道具，但初始次数为 0，只在已选入当前道具组时按局内三消掉落规则增加次数。

「狗了个狗」从第 1 关开始，每次进入、重开或重试都生成新的关卡尝试。每次尝试生成新的 `runSeed`，由它驱动完整棋盘、方块、冻结方块、幻化方块、磁吸方块、双生方块、锁槽数量与其他已配置特殊机制。机制随机使用独立的可复现随机流：磁吸目标选择与钥匙掉落互不消耗对方随机序列。生成器在玩家看到棋盘前完成结构、组合、无道具可解性与难度验证；不合格候选丢弃并重抽。`runSeed` 写入回放元数据，使随机结果可复现。

冻结方块、幻化方块、磁吸方块、双生方块与锁槽作为本方案特殊机制。一个关卡可同时启用多种方块机制；锁槽属于关卡级容量机制，不占方块机制槽；单个方块最多承载一种特殊机制。机制类型由关卡配置固定，`runSeed` 只随机数量、位置、图案与状态。未来新增机制接入同一生成、求解、难度与视觉验证流程。

### 特殊机制数量递进配置

特殊机制数量按现有关卡进度档位显式配置，不直接由总方块数推导。每种机制独立拥有一组 `min/max` 范围；当前首版目标曲线如下：

| 关卡档位 | 冻结方块 | 幻化方块 | 磁吸方块 | 双生方块 |
| --- | ---: | ---: | ---: | ---: |
| 1–5 | 1–2 | 1–2 | 1–2 | 1–2 |
| 6–15 | 2–3 | 2–3 | 2–3 | 2–3 |
| 16–30 | 2–4 | 3–4 | 2–4 | 2–4 |
| 31+ | 3–4 | 3–5 | 3–4 | 3–4 |

档位由 `getProgressStage(levelNumber)` 解析。`runSeed` 只在当前机制的范围内随机本次尝试的具体数量；同一 `runSeed` 与生成器版本必须复现相同数量。总特殊机制密度按逻辑方块权重计算：普通、冻结、幻化、磁吸各计 1 个逻辑单位，双生计 2 个逻辑单位；锁槽不计入 6% 方块机制密度，但计入暂存槽压力、无道具求解、难度与预计时长。候选仍需通过棋盘容量、总机制密度、组合约束与无道具可解性验证。

### 锁槽、扩容与钥匙

基础暂存槽有 7 个总槽位。本次关卡尝试按 `runSeed` 随机生成 0–2 个上锁槽；上锁槽位于右侧连续区域，初始有效容量为总槽位减去上锁槽数。锁槽持续显示锁定视觉；`L=0` 时不显示锁槽。

钥匙是固定 7 种道具集合中的常规道具，用户仍可选择它，即使本关锁槽数为 0。钥匙初始次数为 0；只有钥匙已选入当前道具组且本关存在锁槽时，成功三消才可能按配置命中率掉落次数。首版命中率为 30%，由独立 `keyDropRng` 判定；达到本局锁槽数后停止判定。钥匙掉落在三消/道具结算动画完成后反馈，钥匙图标飞入道具摘要并增加一次使用次数。

最后一次通关三消不掉落钥匙；每次结算后若剩余棋盘逻辑方块数不超过当前空闲有效槽位，也不判定掉落。双生按 2 个逻辑单位计算，磁吸目标是棋盘已有方块，不重复计数。任意来源的三消都可触发一次掉落判定，包括普通点击、特殊机制入槽与道具效果；同一次原子操作最多判定一次。

钥匙无目标，点击后按左到右顺序解锁一个上锁槽，播放钥匙插入与槽位开启动效，成功使用扣 1 次。钥匙上限为锁槽数；失败、重开、通关后清空局内次数。扩容道具仍每关最多使用一次；使用后总槽位与有效槽位各增加 1，锁槽数与钥匙上限不变。新增有效槽位插入右侧连续锁槽之前；已有方块逻辑顺序不变。

### 磁吸方块、消磁仪与双生方块

磁吸方块进入暂存槽时先占用自身槽位，再从非磁吸、真实图案不同的候选中随机吸取 1 个方块。优先候选为可点击方块；若不存在，再从不可点击方块中选择；仍不存在合法候选时磁吸方块独自入槽。磁吸不能吸引磁吸方块，因此不产生连锁。被吸方块作为独立方块进入暂存槽，保留并触发自身机制与动效；磁吸目标选择由 `runSeed` 派生的独立随机流驱动。

磁吸方块与被吸方块的入槽是一次原子操作：磁吸方块先入槽，目标完成吸引动效后入槽，目标机制完成转换/揭示/分裂，再统一处理三消与胜负。中间状态不判失败；最终因槽位满且无三消而失败属于玩家操作结果，不做安全拦截。磁吸完成一次吸引后消耗磁性，暂存槽内按普通方块参与三消。

消磁仪是目标型常规道具，基础次数按现有道具档位为 1–2 次；磁吸机制配置压力较高时按关卡档位提高，不读取本次尝试实际磁吸数量。消磁仪仅能选择棋盘中可点击的磁吸方块；取消、无效目标、无目标与次数用尽不扣次。成功后只移除磁性，保留图案、位置、层叠与其他状态，不入槽、不三消；播放原位消磁动效后恢复普通可点击视觉。

双生方块在棋盘上是 1 个层叠对象，进入暂存槽后分裂为 2 个独立同图案方块，各占 1 个逻辑槽位。两个方块按连续两次普通同图案入槽处理，插入已有同图案队列后方并保持相邻；分裂后不保留双生状态。生成器与求解器按 2 个逻辑方块计数，每种图案的逻辑总数仍为 3 的倍数；层叠与解锁按 1 个棋盘对象处理。

双生方块剩余空槽不足 2 个时仍允许玩家点击，不做安全控制；完成分裂、三消后若最终超过有效容量则失败，属于玩家判断。磁吸吸入双生方块时沿用双生分裂规则。

所有特殊机制方块必须持续显示静态识别动效。特殊状态仍存在时，动效覆盖棋盘与暂存槽；磁性消耗、双生分裂、幻化揭示或其他状态清除后停止对应动效。吸引、消磁、分裂与锁槽解锁均需有可观察的专属动效，动画期间锁定冲突输入。

## User Stories

1. 作为首次进入「狗了个狗」的用户，我希望看到本关棋盘后再选择道具组，以便根据当前关卡情况做选择。
2. 作为首次进入「狗了个狗」的用户，我希望看到固定道具集合中的全部 7 种道具，以便了解可选能力。
3. 作为用户，我希望看到每种道具的名称、图标、效果说明与本关次数，以便判断是否选择。
4. 作为用户，我希望选择恰好 3 种不同道具，以便形成当前关卡的道具组。
5. 作为用户，我希望选择完成后看到显式确认，以便避免误提交道具组。
6. 作为用户，我希望在最终确认前取消选择，以便不改变当前配置或局面。
7. 作为用户，我希望相同的 3 种道具不能被当作一次变更提交，以便无意义操作不重置局面。
8. 作为用户，我希望已确认的道具组在刷新、离开与回访后保留，以便不重复选择。
9. 作为用户，我希望道具组配置只保存道具类型，不保存次数、棋盘、暂存槽或半局状态，以便局内状态保持清晰。
10. 作为用户，我希望保存的道具 ID 失效时整组配置失效并要求重新选择，以便避免系统静默替换道具。
11. 作为用户，我希望后续关卡默认沿用首次确认的道具组，以便减少重复操作。
12. 作为用户，我希望在本关确认前或挑战结束后进入道具组变更操作，以便调整长期策略而不打断进行中的挑战。
13. 作为用户，我希望道具目标选择、图案选择与道具动画期间不能变更道具组，以便避免并发状态冲突。
14. 作为用户，我希望确认新道具组前可以取消编辑，以便不丢失当前进度。
15. 作为用户，我希望确认不同道具组后当前关卡局内进度被重置，但已确认的通关、奖励与解锁不回滚，以便变更有明确代价又不影响历史进度。
16. 作为用户，我希望道具组变更沿用当前关卡的 `runSeed`、棋盘与特殊机制，以便只比较道具组差异。
17. 作为失败结果页用户，我希望变更道具组后回到当前关卡重试，以便使用新组重新挑战。
18. 作为通关结果页用户，我希望变更道具组影响下一关而不是重开已完成关卡，以便历史通关保持完成状态。

### 道具组 UI 交互补充

- 首次进入游戏后先展示已生成棋盘；道具组选择以独立 modal 浮层呈现，浮层遮罩游戏内容但不把选组卡片插入棋盘与暂存槽常规布局。浮层顶部不生成 `DOG · LOADOUT` 这类红色简要说明。
- 浮层继续承载 7 种道具、3 选、显式确认、取消/返回修改与换组二次确认；首次选择操作按钮文案为“清空 / 确认”，更换操作按钮文案为“取消 / 确认”；二次确认保留“返回修改 / 确认更换”语义；取消或返回修改不改变当前道具组及局内状态。
- 已确认道具组在暂存槽上方直接显示 3 个 48px 蓝色方块缩略图占位，使用白色首字；不显示浅蓝摘要底色、左侧“道具组”说明或道具长名称；占位保留完整可访问标签。摘要与棋盘保持 8px 间距，最右侧提供蓝色纯文字“变更”按钮。
- 已确认道具组运行时只保留上述顶部缩略图，不再渲染独立详情道具区。缩略图右下角显示当前剩余使用次数；可用无目标道具点击缩略图后直接执行；目标型道具点击后进入目标选择，目标提示与取消入口仍位于顶部摘要区域。
- 道具不可用时，缩略图整体置灰并禁用点击；不可用条件包括次数为 0、道具未选、当前状态不允许或输入处于锁定状态。每次状态变化后重新计算缩略图可用性。
- 暂存槽不显示独立“暂存槽”标题/计数文案；槽位使用当前容量生成单行网格，容量增加后不换行，槽块宽高按可用宽度自动缩放。
- 游戏头部提供只读的本关特殊机制说明入口；弹窗仅列出当前关卡已配置机制与简要规则，不改变棋盘、暂存槽、道具次数或其他游戏状态。
- “变更”按钮只在本关准备态或挑战结束结果页可用；挑战进行中、目标选择、道具动画、结算与结果确认期间保持禁用。重新选择继续复用 ticket 02 的持久化、`runSeed`、重置、奖励与解锁语义。
19. 作为用户，我希望每种道具的次数独立计算，以便一个道具用尽不影响其他道具。
20. 作为用户，我希望道具成功使用后才扣除 1 次，以便无效目标、取消与不可用状态不消耗次数。
21. 作为用户，我希望基础道具次数按关卡配置处于 1–2 次范围，以便能力有限但可规划。
22. 作为用户，我希望特殊机制数量上限或密度较高的关卡为对应道具提供额外次数，以便高机制压力与可用能力匹配。
23. 作为用户，我希望额外次数由关卡配置与难度档决定，而不是由本次随机棋盘的实际数量决定，以便同一关重试规则稳定。
24. 作为用户，我希望道具使用必须由我主动触发，以便不会发生系统自动消耗。
25. 作为用户，我希望无目标道具点击后直接执行，不再弹出多余确认，以便操作流畅。
26. 作为用户，我希望需要选目标或图案的道具在最终确认前可以取消，以便避免误用。
27. 作为用户，我希望道具使用是原子操作，效果未完整完成时不进入半执行状态，以便局面可预测。
28. 作为用户，我希望游戏永不提供撤销，以便每次选择与道具使用都保持单向结果。
29. 作为用户，我希望道具效果不会直接导致当前局失败，以便道具始终是辅助能力。
30. 作为用户，我希望失败结果确认后不能再使用道具救局，以便结果状态明确。
31. 作为用户，我希望没有合法目标、次数用尽或关卡结束时道具被禁用，以便避免无效操作。
32. 作为用户，我希望一次“道具三消移除”可以选择暂存槽中相邻的两个同图案普通方块，以便清理当前压力。
33. 作为用户，我希望暂存槽存在合法相邻方块对时系统自动从棋盘补 1 个同类普通方块并一次移除，以便完成完整三消。
34. 作为用户，我希望暂存槽只有 1 个同图案或同图案不相邻时不能使用三消移除，以便目标条件清晰。
35. 作为用户，我希望补充方块直接参与三消而不是回到暂存槽，以便道具效果语义清楚。
36. 作为用户，我希望补充方案优先选择被遮挡方块，但仍保留无道具可解路径，以便兼顾解压与可解性。
37. 作为用户，我希望系统自动选择补充方块，不要求我逐个指定，以便减少复杂操作。
38. 作为用户，我希望没有合法补充方案时道具失败且不扣次数，以便错误条件可恢复。
39. 作为用户，我希望补充与移除有完整动画提示，以便理解棋盘变化。
40. 作为用户，我希望暂存槽容量提升道具点击后立即增加 1 个总槽位与有效槽位，以便马上缓解槽位压力。
41. 作为用户，我希望暂存槽容量提升每关最多使用一次，以便保持关卡约束。
42. 作为用户，我希望容量提升只影响当前尝试，通关、失败、重开与新关卡后恢复基础总容量 7 格并重新计算锁槽。
43. 作为用户，我希望使用万能方块后从本关全部图案类型中选择一种，以便补足关键三消。
44. 作为用户，我希望万能方块选择前可以取消，以便避免选错图案。
45. 作为用户，我希望万能方块转化后进入暂存槽并保留高亮边框，以便与普通方块区分。
46. 作为用户，我希望万能方块使用时自动减少棋盘中一个不可点击的同图案方块，以便维持关卡可解性。
47. 作为用户，我希望万能方块只在存在合法图案、槽位与后续局面时可用，以便不会造成失败。
48. 作为用户，我希望追加万能方块前槽尾连续同款中存在冻结方块时，该冻结方块可优先参与本次三消，以便捷径解除当前冻结压力。
49. 作为用户，我希望追加万能方块前槽尾连续同款由冻结与普通方块组成时，两者都可参与本次三消，以便遵守严格追加与连续三消规则。
50. 作为用户，我希望万能方块参与的三消只处理暂存槽中连续相邻的三个同图案方块，以便与基础三消规则一致。
51. 作为用户，我希望火把可以作用于任意冻结方块，以便根据当前局面选择目标。
52. 作为用户，我希望火把作用于棋盘冻结方块后方块留在原位并变成普通方块，以便不改变空间位置。
53. 作为用户，我希望火把作用于暂存槽冻结方块后立即重新检查三消，以便解冻结果马上生效。
54. 作为用户，我希望检测仪只能作用于棋盘中的幻化方块，以便目标边界清晰。
55. 作为用户，我希望检测仪在棋盘原地揭示幻化方块，不把方块移入暂存槽，以便检测是信息辅助而非直接消除。
56. 作为用户，我希望检测仪使用期间棋盘锁定，动画结束后恢复点击，以便避免中途操作冲突。
57. 作为用户，我希望直接点击幻化方块也能正常游玩，不依赖检测仪，以便保留无道具解法。
58. 作为用户，我希望幻化方块点击后飞入暂存槽时显现真实图案，以便揭示发生在移动过程中。
59. 作为用户，我希望幻化方块飞入期间占用一个暂存槽位置并锁定棋盘，以便槽位与交互状态一致。
60. 作为用户，我希望幻化方块落入暂存槽后才按真实图案参与三消，以便显现动画不会产生半成品匹配。
61. 作为用户，我希望幻化方块显现后不需要额外文字提示，以便视觉效果承担状态表达。
62. 作为用户，我希望冻结方块仍可像普通方块一样点击并进入暂存槽，以便冻结机制不是点击禁用。
63. 作为用户，我希望冻结方块进入暂存槽后暂不参与普通三消，以便体现冻结压力。
64. 作为用户，我希望每个冻结方块独立统计其进入暂存槽后的其他成功三消，累计 2 次后自动融化，以便无道具路径仍能解除冻结。
65. 作为用户，我希望火把与万能方块只是冻结捷径而不是唯一解法，以便不被强迫选择特定道具。
66. 作为用户，我希望冻结关卡即使不选择火把或万能方块也存在通关路径，以便关卡公平。
67. 作为用户，我希望同一关可以同时出现冻结、幻化、磁吸、双生与锁槽等多种特殊机制，以便关卡规则逐步丰富。
68. 作为用户，我希望单个方块暂不叠加多种特殊机制，以便视觉与交互规则不冲突。
69. 作为用户，我希望机制类型由关卡配置决定，而不是重试时随机新增机制，以便同一关规则预期稳定。
70. 作为用户，我希望配置了某种特殊机制的关卡每次尝试至少生成 1 个对应特殊方块，以便机制确实出现在关卡体验中。
71. 作为用户，我希望同一关每次进入、重开或重试都生成新的棋盘，以便重复挑战有新鲜感。
72. 作为用户，我希望第 1 关也从随机生成开始，以便不存在固定首关例外。
73. 作为用户，我希望棋盘形状、方块位置、层级、普通图案与特殊方块均可随尝试变化，以便每次挑战形成独立局面。
74. 作为用户，我希望同一次尝试内棋盘结果保持稳定，以便操作过程中不会偷偷换盘。
75. 作为用户，我希望离开游戏或刷新后回访未完成关卡时生成新的尝试，以便系统不恢复复杂半局状态。
76. 作为用户，我希望下一关能在当前关卡进行期间后台生成，以便进入下一关时减少等待。
77. 作为用户，我希望重开/重试时允许看到短暂加载，以便系统有时间生成并验证完整棋盘。
78. 作为用户，我希望生成计算不冻结界面，以便加载期间页面仍保持可响应。
79. 作为用户，我希望生成出的棋盘在展示前已经通过验证，以便不会依赖我反复重试才能遇到有解棋盘。
80. 作为用户，我希望随机棋盘仍符合当前关卡难度范围，以便同一关的挑战强度稳定。
81. 作为用户，我希望通关奖励沿用当前奖励公式，以便新随机机制不改变既有积分规则。
82. 作为用户，我希望同一关重玩已完成关卡不重复累计奖励，以便奖励幂等。
83. 作为开发者，我希望每次尝试保留 `runSeed`，以便重现玩家看到的完整随机棋盘。
84. 作为测试者，我希望给定相同 `runSeed` 时完整棋盘、特殊机制与解法可重放，以便测试失败稳定复现。
85. 作为测试者，我希望给定不同 `runSeed` 时可以验证棋盘实际发生变化，以便确认随机尝试没有被旧快照锁死。
86. 作为开发者，我希望随机生成不直接依赖未保存的运行时随机状态，以便回放、诊断与自动化测试可靠。
87. 作为维护者，我希望未来新增特殊机制只需添加游戏侧配置、生成规则、模拟规则与视觉效果，以便不修改公共游戏层。
88. 作为维护者，我希望其他游戏可以拥有自己的道具集合、选择数量、目标规则与次数规则，以便道具系统不被「狗了个狗」绑死。
89. 作为用户，我希望特殊机制数量随关卡进度档位逐步增加，以便后续关卡形成持续的规则压力。
90. 作为维护者，我希望每种特殊机制可以独立配置自己的递进曲线，以便冻结、幻化、磁吸与双生按实际压力分别平衡。
91. 作为用户，我希望看到暂存槽的上锁槽位，以便理解当前有效容量与钥匙价值。
92. 作为用户，我希望每次关卡尝试随机获得 0–2 个锁槽，以便相同关卡拥有可复现但不完全相同的容量压力。
93. 作为用户，我希望上锁槽位位于暂存槽右侧连续区域，以便入槽顺序保持稳定。
94. 作为用户，我希望钥匙作为常规道具出现在 7 种固定道具集合中，以便主动决定是否携带解锁能力。
95. 作为用户，我希望钥匙初始次数为 0，以便钥匙价值来自本局成功三消而非预置库存。
96. 作为用户，我希望钥匙已选入道具组时，成功三消有 30% 配置化概率增加一次钥匙次数，以便通过正常游玩获得解锁机会。
97. 作为用户，我希望钥匙未选入道具组时不会动态加入本局，以便道具组边界保持稳定。
98. 作为用户，我希望钥匙次数不超过本局锁槽数，以便不会产生多余钥匙。
99. 作为用户，我希望钥匙点击后自动解锁下一格锁槽，以便无需额外目标选择。
100. 作为用户，我希望钥匙解锁后立即增加有效容量并播放开锁动效，以便知道下一次入槽空间已经生效。
101. 作为用户，我希望剩余棋盘逻辑方块数不超过当前空闲槽时不再掉落钥匙，以便不在已经可以容纳剩余方块时制造多余奖励。
102. 作为用户，我希望普通点击、特殊机制与道具引发的三消都能参与钥匙掉落判定，以便掉落规则与三消结果一致。
103. 作为用户，我希望通关最后一次三消不再掉落钥匙，以便结果反馈不出现无效奖励。
104. 作为用户，我希望钥匙掉落在三消/道具结算完成后以图标飞入摘要的方式反馈，以便不打断操作。
105. 作为用户，我希望看到磁吸方块的持续磁性识别动效，以便知道该方块会改变入槽结果。
106. 作为用户，我希望点击磁吸方块后看到磁力指向目标、目标飞入暂存槽的吸引动效，以便理解额外方块来源。
107. 作为用户，我希望磁吸优先吸取可点击、非磁吸、真实图案不同的方块，以便磁吸规则可预测。
108. 作为用户，我希望没有可点击候选时磁吸可以吸取不可点击的非磁吸不同图案方块，以便机制不会因遮挡失效。
109. 作为用户，我希望没有合法候选时磁吸方块仍可独自入槽，以便磁吸不会阻塞正常操作。
110. 作为用户，我希望磁吸不能吸引另一个磁吸方块，以便一次操作不会递归吸引大量方块。
111. 作为用户，我希望被吸方块保留冻结、幻化、双生或未来机制并执行自身规则，以便机制组合行为保持一致。
112. 作为用户，我希望磁吸完成一次吸引后消耗磁性，以便暂存槽中的方块按普通方块参与三消。
113. 作为用户，我希望磁吸目标选择由 `runSeed` 可复现，以便相同操作可以稳定重放。
114. 作为用户，我希望磁吸吸入导致暂存槽满仓且无解时正常失败，以便错误判断保留策略代价。
115. 作为用户，我希望消磁仪只可选择棋盘中可点击的磁吸方块，以便目标范围清晰。
116. 作为用户，我希望消磁仪只消除磁性、不移动方块、不触发三消，以便保留棋盘解法选择。
117. 作为用户，我希望消磁仪播放原位消磁动效后恢复普通可点击视觉，以便确认状态已经改变。
118. 作为用户，我希望消磁仪支持取消目标选择且取消不扣次，以便避免误用。
119. 作为用户，我希望看到双生方块的持续识别动效，以便知道一次点击会产生两个方块。
120. 作为用户，我希望双生方块进入暂存槽后播放分裂动效并生成两个独立方块，以便理解槽位数量变化。
121. 作为用户，我希望双生方块的两个方块保持相邻并沿用普通同图案入槽顺序，以便三消排序可预测。
122. 作为用户，我希望双生方块在空槽不足两个时仍可点击，以便游戏不替我判断这次风险。
123. 作为用户，我希望双生方块最终超出有效容量且无法消除时正常失败，以便承担错误选择后果。
124. 作为维护者，我希望双生在棋盘上按一个层叠对象、入槽后按两个逻辑单位处理，以便层叠与三消模型同时正确。
125. 作为维护者，我希望每种图案的逻辑总数仍是 3 的倍数，以便加入双生后关卡仍具备基础三消闭合性。
126. 作为用户，我希望所有特殊机制方块都有持续静态识别动效，以便不依赖额外文字记忆规则。
127. 作为测试者，我希望磁吸目标随机流与钥匙掉落随机流相互独立，以便新增掉落不会改变既有磁吸回放。

## Implementation Decisions

- 道具系统属于具体游戏。公共层只保存并传递不透明的游戏专属道具组配置，不理解道具效果、目标与次数。
- 「狗了个狗」固定道具集合为 7 种：道具三消移除、暂存槽容量提升、万能方块、火把、检测仪、消磁仪、钥匙；用户首次进入时选择 3 种不同道具。机制方块与锁槽不占道具组名额。
- 当前道具组跨关卡顺延；道具次数不跨关卡、不跨游戏、不形成库存，不写入公共游戏进度。
- 道具次数按关卡配置初始化。普通道具与消磁仪基础范围为每种道具每关 1–2 次；特殊机制数量上限或密度较高时，可按当前关卡进度档位提高冻结对应道具、幻化对应道具与磁吸对应消磁仪的次数。提高值不读取当前 `runSeed` 的实际特殊方块数量，因此同一关重开、重试、刷新回访与道具组变更时保持稳定。钥匙是例外：已选入时初始次数为 0，由本局掉落规则增加。
- 道具成功使用扣 1 次；无效目标、无合法效果、取消、次数为 0、游戏结束均不扣次数。
- 需要目标或图案选择的道具在最终确认前可取消；无目标道具点击后直接执行。所有确认后的道具效果为原子操作，系统不提供撤销。
- 棋盘方块型目标必须同时满足当前可点击条件；火把、检测仪、消磁仪不得选择不可点击方块。道具三消移除的棋盘自动补充候选同样只允许当前可点击的普通方块；暂存槽目标仍按道具专属规则判断。
- 道具目标选择、图案选择与动画期间锁定普通方块和其他道具输入。失败结果确认后不允许救局。
- 确认后的道具组只渲染顶部缩略图作为运行时道具入口；次数以缩略图右下角角标显示，不可用项以整体灰度与禁用状态表达。详情道具区不属于常规游戏布局。
- 道具效果完成后立即重新计算局面；清空最后一个方块时立即通关。道具效果本身不得把当前局直接变成失败。
- 道具三消移除的目标必须是暂存槽中两个相邻、同图案、无特殊机制的方块。系统只从当前可点击的棋盘普通方块中自动补 1 个同款，补充方块直接与选中的槽内方块组成完整三消并移除，不回到暂存槽；没有合法相邻方块对或补充方案时不可用。
- 道具三消移除先过滤会破坏无道具可解路径的补充方案，再只从当前可点击方块中按关卡稳定顺序选择；没有合法方案时失败且不扣次数，不使用随机。
- 暂存槽容量提升无目标、点击即执行；当前尝试总槽位与有效槽位各增加 1 格；每关最多使用一次；上锁槽数与钥匙次数上限不变；新增有效槽位位于右侧连续锁槽之前；通关、失败、重开或新关卡后失效。
- 暂存槽展示不依赖标题或计数文案；槽位始终按当前容量保持单行，容量变化只调整槽位网格列数与槽块尺寸，不产生换行。
- 万能方块需要从本关全部图案类型中选择一种。选择可取消；选择后转化并进入暂存槽，保留高亮边框。
- 万能方块使用必须完成原子转化、入槽、一个不可点击同图案棋盘方块补偿与三消结算；不存在合法选项或可能导致失败时禁用。
- 万能方块严格追加到暂存槽末尾；仅追加前槽尾两个连续同款可与万能完成当前三消，其中冻结与普通同款均可参与。非后缀同款不跨位重排；未参与的冻结方块不会被永久融化。
- 火把可作用于当前可点击的棋盘冻结方块或暂存槽冻结方块。棋盘冻结方块留在原位并变成普通方块；暂存槽冻结方块解冻后立即重新检查三消。
- 检测仪只能作用于当前可点击的棋盘幻化方块。确认后原地播放显现效果，目标转为普通方块；不入槽、不触发三消；动画期间锁定棋盘。
- 冻结方块可以正常点击并进入暂存槽，但携带冻结视觉效果；进入暂存槽后不参与普通三消。每个冻结方块独立统计其后的其他成功三消，累计 2 次自动融化。
- 火把与万能方块是冻结捷径，不是冻结关卡的唯一解法；无道具路径必须依赖冻结方块自然融化或其他基础规则完成。
- 幻化方块只出现在棋盘，带 mask 幻化视觉并显示伪装图案。其出现、位置、真实图案与伪装图案按关卡尝试生成，本次尝试内保持稳定。
- 直接点击幻化方块后，方块进入飞入暂存槽动画；飞行过程中显现真实图案。飞行期间占用 1 个槽位并锁定棋盘；落入暂存槽后才按真实图案正式入槽、重排与检查三消，结算后恢复点击。
- 幻化方块不依赖检测仪；直接点击仍属于无道具路径。检测仪只是提前揭示信息的捷径。
- 特殊机制由关卡配置固定允许类型；一个关卡可以同时启用冻结、幻化、磁吸、双生与锁槽。每种方块机制独立配置按关卡进度档位解析的 `min/max` 数量范围。当前首版档位为 1–5、6–15、16–30、31+；冻结、磁吸、双生范围为 1–2、2–3、2–4、3–4，幻化范围为 1–2、2–3、3–4、3–5。锁槽数独立按本次 `runSeed` 随机为 0–2。总方块机制密度按逻辑单位权重计算，双生计 2、其他方块机制计 1；锁槽不计入 6% 方块机制密度，但进入容量压力与难度指标。
- 特殊机制数量解析集中在游戏侧生成配置 seam：原始配置按档位保存，生成器向下游传递当前关卡已解析的 `min/max`；方块分配、可解性搜索与运行时不重复解释递进公式。单个方块仍最多承载一种特殊机制。
- `runSeed` 在新关卡尝试开始时生成，驱动棋盘形状、方块位置、层级、图案、特殊机制数量/位置/状态、锁槽数与幻化伪装/真实图案。磁吸目标选择与钥匙掉落使用由同一 `runSeed` 派生的独立随机流。单个方块最多承载一种特殊机制。
- 新关卡尝试包括进入、显式重开、失败结果页重试、离开/刷新后回访。道具组变更不是新尝试，沿用原 `runSeed`、棋盘与特殊机制，只重置局内状态与次数。道具组仅在确认当前关卡前或挑战结束后可更换；失败结果页换组重试当前关卡并沿用原 `runSeed`，通关结果页换组作用于下一关并生成新尝试。
- 第 1 关取消固有关卡快照，统一走随机生成 pipeline。已有固定首关公开值、旧固定首关测试与直接导出需要迁移到新的关卡尝试模型。
- 生成候选在展示前验证棋盘结构、三消数量、机制组合、锁槽容量、逻辑方块权重、无道具可解性与当前关卡难度目标。验证必须模拟冻结自然融化、幻化真实图案揭示、磁吸真实候选随机结果、双生分裂、锁槽限制与其他已启用机制。
- 无道具可解性定义为至少存在一条不使用道具的通关路径；路径可包含自然冻结融化、直接点击幻化方块、磁吸自动吸引与双生分裂，但不使用钥匙、消磁仪、扩容或其他道具。锁槽在该路径中保持上锁。候选验证只发布通过的棋盘；不合格候选重抽，超过上限使用仍通过验证的受控 fallback。
- 难度指标、无道具求解与预估时长纳入实际特殊机制；磁吸/双生的逻辑单位、锁槽造成的有效容量压力、自动入槽与玩家错误风险都进入指标；随机候选超出当前关卡难度目标范围即重抽。
- 特殊机制数量曲线属于生成器公共输入。修改曲线必须提升生成器版本；若继续支持旧回放，旧生成器版本必须继续使用旧数量策略，不得用新曲线重解释旧 `runSeed`。
- 通关奖励沿用现有奖励公式，根据本次生成结果的难度指标计算；不引入新的奖励公式。已完成关卡重复挑战不重复累计奖励。
- `runSeed` 与生成器版本、关卡号、尝试信息进入回放元数据。随机生成使用“外部新种子、内部可复现 seeded random”；关卡逻辑不直接依赖未保存的 `Math.random()` 状态。
- 新关卡生成允许短暂加载；下一关优先后台预生成；复杂生成放 Web Worker，避免主线程阻塞。加载期间不得展示未验证候选。
- 所有特殊机制方块必须持续显示静态识别动效；道具使用必须有对应视觉效果。磁吸吸引、消磁、双生分裂、锁槽解锁必须有专属动效；不强制增加 `显现中`、`检测中`、`融化中` 等文字状态文案。
- 关卡头部的特殊机制说明入口只提供只读说明；说明弹窗不得触发道具、改变棋盘、修改暂存槽或绕过输入锁。
- 保留现有方块飞入、三消、通关与失败时序作为基准；新增道具动画首版使用统一约 360ms 基准，人工视觉 QA 后可微调。
- 现有游戏状态仍以 `playing`、`won`、`lost` 为核心结果；动画只是输入锁与视觉反馈的暂态，不创建可恢复的半局公共存档。
- 现有公共进度继续只保存用户、游戏进度、奖励、解锁与游戏专属道具组配置；不保存次数、棋盘、暂存槽或进行中的 `runSeed`。
- 未来特殊机制必须提供生成规则、状态模拟、难度影响、可解性参与方式与视觉效果，并接入同一候选验证 seam；未来机制不允许默认污染公共层。

### 新增机制与道具的运行时契约

- `GameSession` 继续作为最高状态规则 seam，负责有效容量、锁槽、棋盘剩余逻辑单位、暂存槽逻辑单位、双生分裂、磁吸原子入槽、三消、通关与失败。运行时不得以物理棋盘对象数替代逻辑方块单位数。
- 关卡生成器继续作为最高随机与可解性 seam，接收关卡号、配置与 `runSeed`，输出包含锁槽配置、特殊机制数量、逻辑方块权重与可回放随机元数据的完整关卡。磁吸目标随机与钥匙掉落随机使用独立派生流；求解器快照必须包含对应随机流位置。
- `DogItemRuntime` 扩展为 7 种道具定义。消磁仪使用现有目标型道具阶段：进入目标选择、只暴露可点击磁吸方块、可取消、成功后原子移除磁性并扣次。钥匙使用现有无目标道具阶段：点击即解锁一格并扣次；钥匙次数由游戏局内事件增加，不属于跨关道具组配置。
- 道具组编辑器仍要求 3 个不同 ID，但候选集合为 7 个。确认道具组即开始本关；进行中的挑战禁止换组。失败/通关结果页允许换组，并按结果页语义分别重试当前关卡或作用于下一关。
- 游戏 controller 与动画层复用现有输入锁、方块飞入、三消反馈、道具动画完成回调与结果呈现流程，新增吸引、消磁、分裂、开锁、钥匙掉落反馈；动画完成前不开放冲突输入，不在中间状态判胜负/失败。
- 机制渲染层必须为磁吸、双生、冻结、幻化提供持续静态识别动效；特殊状态消费或清除后停止对应动效。静态识别不依赖常驻文字。
- 钥匙掉落事件在任意来源三消中共享同一结算入口；终局三消、剩余逻辑棋盘单位数不超过当前空闲有效槽、钥匙未选入、锁槽数为 0 或钥匙达到锁槽上限时跳过掉落判定。其余合法事件按阶段配置的 30% 命中率判定，单次原子操作最多一次。
- 磁吸入槽顺序固定为磁吸源先入槽、目标后入槽；目标按自身机制完成入槽规则后统一三消。候选过滤排除磁吸方块，优先可点击、真实图案不同，随后才考虑不可点击候选；没有合法候选时源方块独自入槽。磁性在本次吸引完成后消费。
- 双生按一个棋盘层叠对象与两个入槽逻辑单位建模。分裂后的两个方块沿用普通同图案插入顺序并保持相邻；不因空槽不足提前禁用，最终超有效容量且未消除时才失败。
- 公共游戏进度只保存用户、游戏进度、奖励、解锁与游戏专属道具组配置；不保存锁槽数、钥匙次数、消磁仪次数、双生/磁吸局内状态、棋盘、暂存槽或进行中的 `runSeed`。

## Testing Decisions

- 测试只验证用户可观察行为、公开生成结果与领域不变量，不锁定私有函数、内部数组排列、单帧动画或实现算法。
- 主测试 seam 为关卡生成器：给定关卡配置与显式 `runSeed`，验证输出是完整、可回放、通过验证的关卡。使用不同种子验证棋盘确实可变化；使用同一种子验证完整结果一致。
- 生成器测试覆盖第 1 关起随机生成、棋盘形状、层级、方块位置、图案数量、四个机制数量档位及边界、机制数量非回退、机制组合、总密度、单方块不叠加与难度范围。
- 生成器测试覆盖候选失败、重抽、受控 fallback、生成预算、加载/后台预生成结果与 `runSeed` 回放。
- 无道具可解性测试必须模拟真实特殊机制：冻结方块进入槽后自然融化计数、幻化方块点击后的真实图案揭示、连续相邻三消与同次多组三消。
- 无道具路径测试必须模拟锁槽永久保持上锁、磁吸真实随机目标、双生逻辑单位分裂、冻结自然融化、幻化真实图案揭示、连续相邻三消与同次多组三消；不使用钥匙、消磁仪或扩容道具。
- 随机机制测试验证相同 `runSeed` 与相同操作路径复现磁吸目标、钥匙掉落、锁槽数与关卡结构；不同种子可变化；独立随机流不会因钥匙判定改变磁吸目标序列。
- `GameSession` 测试覆盖基础选择、槽位容量、三消、冻结状态、自动融化、万能方块优先级、棋盘补偿、失败/通关边界与不可撤销行为。
- `GameSession` 测试覆盖 0–2 锁槽、有效容量与空闲槽计算、扩容后锁槽位置/容量关系、钥匙逐格解锁、双生分裂、逻辑单位计数、磁吸源/目标原子入槽、特殊目标自身规则、无目标磁吸与最终超容量失败。
- `GameSession` 测试覆盖道具效果的原子性：成功扣次、失败不扣次、取消不改局面、道具不会制造失败、失败确认后不能救局。
- `GameSession` 测试覆盖道具三消移除的相邻槽内方块对、非相邻拒绝、自动补一个、补充优先级、无合法方案与无道具可解路径保留。
- `GameSession` 测试覆盖万能方块的图案选择、取消、不可点击同款补偿、冻结优先、普通同款补足与高亮区分数据。
- 游戏 controller 测试覆盖幻化方块飞行期间的槽位占用、棋盘输入锁、落槽后真实图案三消与恢复点击；检测仪原地揭示不入槽；火把解冻位置保持。
- 游戏 controller 测试覆盖磁吸吸引、被吸幻化/冻结/双生的自身动效、磁性消耗、消磁原位动效、双生分裂、锁槽开锁、钥匙掉落反馈、输入锁、动画完成后恢复输入与结果状态一致。
- 游戏 controller 测试覆盖道具目标选择、图案选择、取消、输入锁、合法目标高亮、非目标方块置灰、视觉效果完成后恢复输入与结果状态一致；消磁仪只暴露可点击磁吸目标，钥匙无目标自动执行。
- 道具组与进度测试覆盖首次选择 7 种中的 3 种、显式确认、取消、同组不变更、准备态确认即锁定、挑战中禁止换组、结果页换组、跨刷新/离开保留、失效 ID 整组失效、失败页沿用 `runSeed`、通关页作用于下一关、完成进度不回滚。
- 道具次数测试覆盖基础 1–2 次、特殊机制档位提高对应次数、同关重试次数稳定、实际随机特殊方块数量不改变次数。
- 道具次数测试覆盖钥匙初始 0、未选钥匙不掉落、锁槽数 0 不掉落、30% 配置化掉落、上限封顶、终局/低于空槽阈值跳过、任意来源三消最多一次、失败/重开/通关清空；消磁仪次数按磁吸配置档位初始化。
- `ProgressStore` 测试继续验证公共进度不保存棋盘、暂存槽、次数、半局状态或 `runSeed`；刷新回访生成新尝试。
- 应用 UI 测试覆盖首次进入棋盘与道具组选择、道具展示、道具视觉效果、重试加载、通关/失败结果、换组流程与无强制文字状态文案。
- 应用 UI 测试覆盖道具组选组 modal 浮层、遮罩层、无红色简要说明、两种按钮文案、左右道具卡片、48px 蓝色白字首字缩略图摘要、摘要与棋盘 8px 间距、最右侧蓝色纯文字“变更”按钮及锁定状态；移动端验证浮层滚动与摘要紧凑布局。
- 应用 UI 测试覆盖运行时详情道具区不存在、顶部缩略图直接触发无目标道具、次数角标、不可用整体置灰/禁用、目标型道具目标提示与取消、合法目标高亮及槽内非目标方块置灰；覆盖容量变化后暂存槽单行展示及槽块随容量缩放。
- 应用 UI 测试覆盖特殊机制说明入口、机制弹窗内容、关闭行为及说明过程不改变游戏状态。
- 随机回归测试使用固定测试种子生成 1–100 个连续关卡，并固定覆盖关键关卡；失败输出 `runSeed`、关卡号、生成器版本与回放信息。
- 随机回归测试必须验证多个 `runSeed` 的候选不被固定首关快照或旧确定性入口覆盖。
- 端到端测试覆盖注册、目录、进入游戏、道具组选定、重试、离开/刷新、结果页与进度保存；不重复验证所有纯状态规则。
- 视觉测试验证冻结特效、幻化 mask 动效、飞行中显现真实图案、万能高亮、火把/检测仪/道具使用效果、输入锁与移动端布局。
- 视觉测试验证所有特殊机制持续静态识别动效、磁吸脉冲与目标飞入、消磁标识消失、双生分裂、锁槽锁定/解锁、钥匙掉落图标反馈；测试只锁定可观察状态与时序，不锁定具体 CSS 或单帧像素。
- 生成器、公共契约、进度、导航、游戏启动、Worker 或难度搜索改动属于跨模块范围，完成前运行全量 QA；视觉/DOM/动画改动优先运行 UI 测试，响应式改动追加跨浏览器测试。

## Out of Scope

- 未知蒙层机制；检测仪本期只处理幻化方块。
- 同一方块叠加冻结、幻化或未来其他多种特殊机制；本期单个方块最多一种机制。
- 除冻结方块、幻化方块、磁吸方块、双生方块与锁槽外的其他特殊机制实现；未来机制只保留可扩展 seam。
- 撤销、回退、悔棋与任何道具效果撤销。
- 自动使用道具、自动选择目标、道具造成失败、失败后的道具救局。
- 跨游戏公共道具目录、统一道具效果、全局道具库存或可交易道具。
- 后端、云同步、排行榜、社交、广告、分享、真实账号与多用户。
- 半局状态、棋盘、暂存槽、次数与 `runSeed` 的公共持久化恢复。
- 为每种随机棋盘单独设计新奖励公式；奖励继续沿用当前公式。
- 强制文字状态提示；视觉效果之外的完整教学、旁白与引导文案。
- 首版曲线之外的后续特殊机制比例、道具次数切换阈值、视觉资源美术稿与后续机制的最终平衡值；这些由后续关卡配置与试玩迭代确定。

## Further Notes

- 本 spec 以领域词汇与现有 ADR 为准：游戏拥有自己的道具规则；`可解关卡` 至少存在一条无道具通关路径；`道具后可解局面` 仍需保留普通通关路径；三消必须由暂存槽中连续相邻的三个同图案方块组成。
- 当前实现的确定性生成、固定首关入口、公共游戏启动契约、奖励生成输入与现有生成器测试需要迁移，但不应破坏已有通关奖励幂等、进度隔离与基础三消行为。
- `runSeed` 的随机性是玩家视角的随机；系统内部必须保留可回放输入。直接在关卡逻辑中调用未保存的运行时随机状态会使问题无法复现。
- 生成器只把通过验证的候选交给游戏；运行时若发现状态不变量异常，保留 `runSeed` 与操作日志，暂停局面并提供显式重新生成/报告路径，不静默掩盖 Bug。
- 本 spec 采用的测试 seam 已确认：关卡生成器作为主 seam，`GameSession` 作为状态规则 seam，公共 App/游戏 controller 作为用户流程与视觉 seam。
- 仅本 spec 文档变更不运行测试；实现开始后按项目 ticket 验收规则记录实际验证命令与结果。
