# v13 集中配置是「狗了个狗」的唯一行为来源

「狗了个狗」v13 使用一份经过校验且深度冻结的集中配置，作为关卡、特殊机制、难度、道具、动画、资源、音效与测试 profile 的唯一可调参数来源。配置 schema 版本为 13；生成器版本、关卡上限、逻辑方块增长、暂存槽与锁槽边界、`floor(N × 0.30)` 机制预算、四类机制逻辑权重、道具次数例外、难度目标与验证 profile 都必须从该配置读取。

## 决策

- `loadDogV13Config` 在配置进入生成器或游戏启动边界时执行必填字段、类型、范围、枚举、唯一性与跨字段关系校验。
- 校验失败抛出包含字段路径、错误类别与可读消息的诊断错误；生成器和游戏启动都在创建或展示候选棋盘前失败，不静默回退到旧配置。
- 特殊机制预算先按逻辑方块总数 `N` 计算 `floor(N × 0.30)`，再用稳定 round-robin 余数策略按冻结/幻化/磁吸权重 1、双生权重 2 分配；四类必须出现，单个方块最多承载一种机制。
- `focused`、`smoke`、`full` profile 由配置统一声明；生成器、游戏启动与 QA 选择结果使用同一 profile seam。
- 现有旧导出常量可暂时作为迁移 adapter，必须标记为 adapter，且不能再增加新的散落可调参数。ticket 24–28 完成后清除不再需要的 adapter。

## Consequences

配置结构比单个运行时模块更宽，变更需要同步校验与 profile。好处是关卡、运行时、视觉与 QA 不会各自解释相同规则；无效配置在用户看到未验证棋盘前被拒绝，诊断可定位到具体字段。
