# v13 集中配置是「狗了个狗」的唯一行为来源

「狗了个狗」v13 使用一份由完整 TypeScript 类型约束、在模块初始化时复制并深度冻结一次的集中配置，作为关卡、特殊机制、难度、道具、动画、资源、音效与 UI 的唯一可调参数来源。配置 schema 版本为 13；生成器版本、关卡上限、逻辑方块增长、暂存槽与锁槽边界、`floor(N × 0.30)` 机制预算、四类机制逻辑权重、道具次数例外与难度目标都必须从该配置读取。

## 决策

- 仓内配置源由 `DogV13Config` 约束；字段缺失、字段类型错误和错误枚举由 TypeScript 构建发现。应用使用默认配置，游戏启动、生成器与准备服务只接受类型正确的配置，不重复解析任意输入。
- 默认配置只在模块初始化时复制并深度冻结一次；主线程、游戏运行时、关卡生成器与 Worker 共享该配置作为唯一行为来源。测试如需覆盖配置行为，传入类型正确的替代配置。
- 不为仓内常量维护运行时 schema、字段遍历、问题列表或配置错误类。持久化状态、UUID、关卡请求与回放、Worker 生命周期、道具目标和局内操作仍在真实信任边界校验。
- 特殊机制预算先按逻辑方块总数 `N` 计算 `floor(N × 0.30)`，再用稳定 round-robin 余数策略按冻结/幻化/磁吸权重 1、双生权重 2 分配；四类必须出现，单个方块最多承载一种机制。
- `focused`、`smoke`、`full` profile 属于测试基础设施配置；profile 选择与 QA 编排不进入生产配置、游戏启动或 Worker 载荷。
- 现有旧导出常量如仍有真实消费者，可暂时作为迁移 adapter，必须标记为 adapter，且不能再增加新的散落可调参数；迁移完成后清除不再需要的 adapter。

## Consequences

配置结构比单个运行时模块更宽，变更由 TypeScript 类型和既有高层行为测试共同约束。好处是关卡、运行时与视觉不会各自解释相同规则，也不再维护一套仅重复静态配置的运行时解释器。QA profile 独立维护在测试基础设施中，不会进入生产 bundle。
